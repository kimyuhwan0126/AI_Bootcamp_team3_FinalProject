## 1 · 환경 변수 — 무엇이 있고 무엇이 없나

`.env.local` 에 **키 16개**가 있다. 값은 여기 안 옮긴다.

### 1-1 · 있다

| 키 | 쓰는 곳 | 배포 때 바꾸나 |
|---|---|---|
| `DATABASE_URL` | `lib/db.ts` · `lib/geo.ts` · `lib/places.ts` | 그대로 (운영 Neon) |
| `NEXTAUTH_SECRET` | next-auth · `lib/ratelimit.ts` 의 기기 쿠키 서명 | 그대로. **바꾸면 로그인 세션이 전부 끊긴다** |
| `NEXTAUTH_URL` | next-auth | **반드시 바꾼다** — 아래 §2 ② |
| `KAKAO_REST_API_KEY` | `lib/auth.ts` · `lib/geo.ts` | 그대로 |
| `KAKAO_REDIRECT_URI` | `lib/auth.ts` · `next.config.mjs` | **반드시 바꾼다** — 아래 §2 ③ |
| `NEXT_PUBLIC_KAKAO_JS_KEY` | `app/m/[code]/ui.tsx:327` (지도 SDK) | 그대로. 단 **콘솔에 배포 도메인을 등록**해야 산다 |
| `OLLAMA_PRIMARY_URL` · `OLLAMA_PRIMARY_MODEL` | `lib/ai.ts:44-45` | 그대로 |

### 1-2 · 없는데 코드가 찾는다

| 키 | 찾는 자리 | 없으면 |
|---|---|---|
| **`MOIMER_SALT`** | `lib/auth.ts:30` | **소스에 적힌 기본값을 쓴다.** §2 ① 이 이것이다 |
| `OLLAMA_API_KEY` | `lib/ai.ts:46` | `authorization` 헤더를 안 붙인다 → Ollama Cloud 가 401 → AI 추천만 안 된다. **서비스는 안 멈춘다** |
| `KAKAO_CLIENT_SECRET` | `lib/auth.ts` | 카카오 콘솔에서 Client Secret 을 **꺼 뒀으면 없어도 된다.** 켰다면 **필수** — 안 넣으면 토큰 교환에서 막힌다 |

### 1-3 · 있는데 아무 데서도 안 읽는다 (죽은 키)

`app/` 과 `lib/` 전체를 훑어 `process.env` 로 읽는 자리가 **하나도 없다.**

- `ODSAY_API_KEY` — 대중교통 길찾기를 붙이다 만 자리. 지금 코드에 없다
- `TMAP_APP_KEY` — 같다
- `OLLAMA_FALLBACK_URL` · `OLLAMA_FALLBACK_MODEL` — 대체 모델로 넘기는 코드가 없다. **primary 가 죽으면 그냥 못 붙는다**
- `NEXT_PUBLIC_FF_AI_CHAT` · `NEXT_PUBLIC_FF_PERSONAL` · `NEXT_PUBLIC_FF_REALTIME` · `NEXT_PUBLIC_FF_WEATHER` — 기능 깃발 넷 다 안 읽는다

**앞의 둘(`ODSAY_API_KEY`·`TMAP_APP_KEY`)은 살아 있는 남의 서비스 키다.** 안 쓰는데 파일에 들고 있을 까닭이 없다 —
배포 서버의 환경 변수에는 **넣지 마라.** 쓸 일이 생기면 그때 넣는다.

### 1-4 · 없거나 죽었을 때 멈추나 넘어가나

| 무엇 | 멈추나 |
|---|---|
| `DATABASE_URL` 없음/틀림 | **멈춘다.** `neon()` 이 모듈을 읽는 순간 던진다 → 모든 화면·라우트 500 |
| `NEXTAUTH_SECRET` 없음 | **로그인이 멈춘다.** 덤으로 기기 쿠키 서명이 기본값으로 떨어진다 |
| `NEXTAUTH_URL` 이 배포 주소가 아님 | **로그인이 멈춘다.** 카카오가 옛 주소로 돌려보낸다 |
| `KAKAO_REST_API_KEY` 없음 | **넘어간다.** 카카오 provider 를 아예 안 단다(`카카오준비됨`) — `/me` 에 카카오 단추가 안 그려진다. 동 이름 찾기는 OSM 으로 내려간다(Nominatim 은 **초당 1회**라 느려진다) |
| `NEXT_PUBLIC_KAKAO_JS_KEY` 없음 | **넘어간다.** 모임 화면 지도가 `mapDead` 로 접히고 목록으로만 고른다 |
| `OLLAMA_*` 없음/죽음 | **넘어간다.** 방장이 AI 단추를 눌렀을 때만 20초 뒤 `ai_unavailable` 503, 횟수는 환불된다(`db.refundAi`) |
| `ODSAY_API_KEY` · `TMAP_APP_KEY` 없음 | **아무 일도 안 난다.** 코드가 안 읽는다 |

> ⚠ `NEXT_PUBLIC_` 으로 시작하는 키는 **빌드할 때 코드에 박힌다.**
> 배포 서버에 넣는 것만으로는 안 되고 **빌드하는 자리에 있어야 한다.**

## 2 · 배포 전에 반드시 해야 할 것

### ① `MOIMER_SALT` 를 넣는다 — 사람이 적은 때에

`lib/auth.ts:30` 이 이렇다.

```ts
const SALT = process.env.MOIMER_SALT ?? 'moimer-dev-salt';
```

**지금 이 키가 없어서 소스에 적힌 글자가 그대로 쓰인다.** 이 소금은 두 곳에 쓰인다 —
참가자 PIN 해시와 참가자 쿠키 서명. 소스를 본 사람은 **아무 참가자 쿠키나 스스로 만들 수 있다.**

지금 실제로 뚫리는 폭은 좁다. `db.getView` 가 멤버가 아닌 사람에게는 참가자 `id` 와 좌표를 비워
보내므로(`lib/db.ts:132`), 남의 참가자 id 를 주울 길이 화면에는 없다. 그래도 **소금이 공개된 상태로
밖에 내놓으면 안 된다** — 이 가림막 하나가 뚫리는 날 곧바로 사칭이 된다.

⚠ **넣는 순간 그때까지 저장된 PIN 해시(참가자 465명)와 나가 있는 쿠키가 전부 무효가 된다.**
지금 모임에 들어와 있는 사람들이 다 튕긴다. **모임이 거의 없는 때에 한 번에 해라.**
값은 32자 이상 아무 무작위 문자열이면 된다. **한 번 정하면 다시는 바꾸지 마라.**

### ② `NEXTAUTH_URL` 을 배포 주소로 바꾼다

지금 값은 **`http://localhost:3000`** 이다. 그대로 두면 카카오 로그인이 끝난 뒤
내 컴퓨터로 돌려보내서 아무도 로그인을 못 끝낸다.

`https://<배포도메인>` 으로 바꾼다. `http` 가 아니라 **`https`** 여야 한다 —
참가자 쿠키가 `secure: NODE_ENV === 'production'` 이라(`lib/auth.ts`) 프로덕션에서는
**http 로는 쿠키가 아예 안 붙는다.**

### ③ `KAKAO_REDIRECT_URI` 와 카카오 콘솔을 **함께** 바꾼다

지금 값은 **`http://localhost:3000/api/auth/kakao/callback`** 이다.

이 주소는 세 곳이 같아야 한다. **한 곳만 바꾸면 KOE006 이다** —
그것도 아이디·비밀번호를 다 넣은 **뒤에야** 튕겨서 원인을 짚기 가장 어려운 모양으로 난다.

1. `.env.local` 의 `KAKAO_REDIRECT_URI` → `https://<배포도메인>/api/auth/kakao/callback`
2. **카카오 개발자 콘솔 > 카카오 로그인 > Redirect URI** 에 같은 주소 등록
3. **카카오 콘솔 > 플랫폼 > Web** 에 `https://<배포도메인>` 등록
   (여기를 빠뜨리면 `NEXT_PUBLIC_KAKAO_JS_KEY` 로 뜨는 **지도가 안 뜬다**)

`next.config.mjs` 가 이 값의 길(path)을 읽어 NextAuth 자리로 되돌려 준다 — 코드는 안 건드려도 된다.

> 콘솔에 `/api/auth/callback/kakao` (차례가 반대인 NextAuth 기본 주소)를 등록할 수 있다면,
> `.env.local` 에서 `KAKAO_REDIRECT_URI` 를 **지우는 것**이 더 깨끗하다 —
> `lib/auth.ts` 의 덧옷과 `next.config.mjs` 의 되돌림이 둘 다 저절로 안 붙는다.

### ④ 개발용 guest 로그인 통로를 **닫는다** — ✅ 적용함 (2026-08-13, 논의131)

`lib/auth.ts` 의 `CredentialsProvider({ name: 'guest', … })` 였다.

**닫혔다.** provider 등록 자체를 `개발중`(`NODE_ENV !== 'production'`) 으로 감쌌다 —
화면 단추만 숨기던 것에서 통로 자체를 막는 것으로 바꿨다.

```ts
const 개발중 = process.env.NODE_ENV !== 'production';
...
...(개발중 ? [CredentialsProvider({ name: 'guest', … })] : []),
```

**왜 급했는지(고치기 전 실측)**: 방장 판정이 계정으로 바뀌었는데(`방장인가`, 논의124)
`GET /api/m/<코드>` 는 로그인 없이 참가자 **이름**을 내준다. 초대 코드를 가진 사람이 방장 이름을 읽고
→ 그 이름으로 guest 로그인 → **그 모임의 방장이 됐다**(모임 지우기·강퇴·확정 가능).
운영 DB 에 그때 만들어진 guest 계정 59개, guest 가 방장인 모임 8건이 있었다(시험 자국).

⚠ 닫으면서 감수하기로 한 것: **카카오가 죽어 있는 동안 아무도 모임을 못 만든다**
(논의57 이 이미 그때 멈추는 것이 맞다고 정했다). `tests/` 의 시험 900여 건은 이 길로 로그인하므로
**시험은 개발 서버(`next dev`)에서만 돈다** — 프로덕션 빌드에는 이 통로가 없다는 것을 알고 있어야 한다.

- 시험: `tests/신원.mjs`·`tests/카카오방장.mjs` 등이 `NODE_ENV` 를 안 건드리는 개발 서버에서 계속 돈다.
  프로덕션에서 이 provider 가 실제로 안 뜨는지는 배포 뒤 §4-2 로 확인한다.

### ⑤ 첫 요청이 **모임을 지운다**는 것을 알고 배포한다

`lib/db.ts:819` 의 `가끔청소()` 는 조회 100번에 한 번 도는데,
**서버가 뜬 뒤 첫 조회에서는 반드시 한 번 돈다**(`청소틱++ % 100`, 처음 값이 0).
그 안에서 `sweepIdleMeetings()` 가 **90일 조용한 모임을 지운다**(참가자·후보·표까지 cascade).

즉 **배포하고 누가 모임 화면을 처음 여는 순간 삭제가 한 번 돈다.** 정상 동작이지만,
배포 직후 데이터가 줄어드는 것을 보고 놀라지 않으려면 알고 있어야 한다.
**배포 전에 DB 백업을 한 번 떠 두어라.**

## 3 · 하면 좋은 것

### ⑥ 보안 헤더를 넣는다 — `next.config.mjs` 에 지금 **하나도 없다** ✅ 적용함 (2026-08-14)

`reactStrictMode` 와 카카오 되돌림(rewrite)뿐이었다. `headers()` 도 `poweredByHeader: false` 도 없어서
`X-Powered-By: Next.js` 가 그대로 나갔었다.

`next.config.mjs` 의 같은 export 객체 안에 `rewrites()` 는 그대로 두고, `poweredByHeader: false` 와
`headers()` 를 나란히 추가했다 — `/:path*` 로 아래 다섯 헤더를 모든 경로(페이지·API 라우트 포함)에 붙인다.

```js
poweredByHeader: false,
async headers() {
  return [{ source: '/:path*', headers: [
    { key: 'Strict-Transport-Security', value: 'max-age=63072000; includeSubDomains' },
    { key: 'X-Content-Type-Options',    value: 'nosniff' },
    { key: 'Referrer-Policy',           value: 'strict-origin-when-cross-origin' },
    { key: 'X-Frame-Options',           value: 'SAMEORIGIN' },
    { key: 'Permissions-Policy',        value: 'geolocation=(self), camera=(), microphone=()' },
  ]}];
},
```

`curl -I http://127.0.0.1:3000/` 와 `/api/mine` 로 실제 응답에 다섯 헤더가 모두 실리는 것을 확인했다
(dev 서버 재시작 없이 설정 변경을 그대로 반영했다). `X-Powered-By` 도 사라졌다.

CSP 는 **넣지 않았다** — 범위 밖이다. 카카오 지도 SDK(`dapi.kakao.com`)와 OSM 타일을 스크립트·이미지로
부르고 `next dev` 는 인라인 스크립트를 쓴다 — 급히 넣으면 지도부터 죽는다. 넣으려면 `Report-Only` 로 먼저 재라.

> `geolocation=(self)` 로 둔 것은 출발지 찾기가 위치를 쓰기 때문이다. 안 쓰면 `()` 로 닫아라.

### ⑦ 모임 조회에 횟수 제한이 없다 — ✅ 적용함 (2026-08-14 감사에서 확인 — 코드는 이미 있었고 이 문서만 안 갱신돼 있었다)

`lib/ratelimit.ts` 의 `횟수확인` 을 **`/api/geo` · `/api/places` · `/api/places/search` 셋만** 불렀었다.
`GET /api/m/<코드>` 와 `GET /api/m/<코드>/stream` 은 제한이 없었다.

- 코드는 6자리(헷갈리는 글자를 뺀 32글자)라 경우의 수가 약 10억이다. 통째로 훑기는 어렵지만,
  **한 번 새어 나간 코드는 무제한으로 두들길 수 있다.**
- SSE 쪽이 더 아프다. 연결 하나마다 25초 타이머를 물고 **서버가 하나뿐이다**(`stream-bus.ts` 는 프로세스 메모리).
  같은 코드로 연결을 수천 개 열면 그대로 짐이 된다.

**지금은 둘 다 걸려 있다** — `app/api/m/[code]/route.ts` GET 맨 앞에 `횟수확인('view')`,
`app/api/m/[code]/stream/route.ts` GET 맨 앞에 `횟수확인('stream')` (둘 다 코드 안에 `배포 점검 §3⑦`
이라고 자기 근거를 적어 뒀다). `lib/ratelimit.ts` 의 `길별한도` 에 `view` 전용 한도(30초·300번,
SSE `changed` 재조회를 감안해 기본보다 넉넉히)가 따로 있고 `stream` 은 기본 한도(30초·120번)를 그대로 쓴다.
전용 회귀 시험 `tests/보기제한.mjs` 도 같이 있다 — 2026-08-14 감사에서 다시 돌려 **11개 전부 통과**
확인했다(정상 새로고침은 안 걸림 · 몰아치면 429 · POST 는 안 막힘 · view/stream 은 서로 다른 칸).

언제/누가 넣었는지는 `git log` 로는 못 짚는다 — `git log --oneline -- lib/ratelimit.ts` 에 남은 커밋이
`fix(vercel): app-v2 내용을 저장소 루트로 평탄화` 하나뿐이라, 평탄화 전 `app-v2` 쪽 어느 세션에서
이미 넣어 둔 채로 통째로 옮겨진 것으로 보인다.

### ⑧ 초대 코드만으로 이름과 출발지 이름이 보인다

`db.getView` 는 멤버가 아닌 사람에게 참가자 `id`·`lat`·`lng` 는 지우지만
**`name` 과 `origin_name` 은 그대로 준다.** 즉 코드를 받은 사람은 누가 들어와 있고
각자 어디서 오는지(역·동네 이름)를 참여하지 않고도 본다.

초대 코드가 곧 열쇠인 설계라 **일부러 그런 것일 수 있다.** 다만 배포하면
그 코드가 카톡·SNS 를 타고 돌아다니므로, 이것이 의도인지 사람이 한 번 정하고 가야 한다.

### ⑨ 로그 — 새는 것은 없지만 시끄럽다

`app/`·`lib/` 의 `console.*` **25곳**을 다 봤다. **비밀이 찍히는 자리는 없다.**
키는 늘 헤더에만 실리고, 찍는 것은 상태 코드와 오류 이름뿐이다(`lib/geo.ts:57` 의 `why()` 가 그 규칙이다).

두 곳만 봐 둘 만하다 — 둘 다 비밀은 아니다.

- `lib/ai.ts:122` — AI 응답 본문을 80자까지 찍는다. 그 프롬프트에는 **참가자 출발지 이름과 좌표**가 들어간다.
  응답만 찍으므로 지금은 안 새지만, 프롬프트를 찍는 줄이 하나 늘면 그 순간 샌다
- `lib/db.ts:825` — 청소 결과를 `console.log` 로 찍는다. 수만 찍는다

오류 응답 쪽도 깨끗하다. 화면에는 `not_found`·`forbidden` 같은 **정해 둔 낱말만** 나가고
(`bad()` 한 곳에서 만든다), 카카오 토큰 교환 실패 같은 자세한 글은 서버 기록에만 남는다.
`app/api/places/*` 의 `throw e` 는 500 이 되는데, 프로덕션 Next 는 본문에 스택을 안 싣는다.

### ⑩ `/api/mine` 을 화면 하나가 두 번 부른다 — ✅ 적용함 (2026-08-13, 논의129 뒤처리)

`app/tabbar.tsx:46` 이 **모든 화면에서** `/api/mine` 을 불렀었다 — 탭바가 안 그려지는 화면(`/m/…`, `/new`,
`/join/…`)에서도 `useEffect` 가 `if (!탭.some(…)) return null` **보다 먼저** 돌았기 때문이다.

지금은 `보임 = 탭.some((t) => t.주소 === 지금)` 을 먼저 셈해 `useEffect` 안에서 `if (!보임) return;` 으로
막는다 — 탭바가 안 그려지는 화면에서는 아예 안 부른다. `/meetings` 에서 목록 화면과 겹쳐 나던

## 6 · Vercel 배포 (2026-08-14, `develop-selfhost` → Vercel)

`실서비스` 폴더 전체를 저장소 루트로 깃에 올린 뒤 Vercel 에 연결했더니 빌드가 바로 실패했다.
아래는 그 실패와, 이어서 실제로 확인한 Vercel 전용 함정들이다.

### ① 빌드 실패 "No Next.js version detected" — ✅ 리포 구조를 바꿔서 해소함 (`fix(vercel): app-v2 내용을 저장소 루트로 평탄화`)

저장소 루트의 `package.json`(`{"dependencies":{"pg":"^8.23.0"}}`)에는 `next` 가 없었다 — 진짜 Next.js
앱은 `app-v2/` 안에 있었다. Vercel 기본값은 저장소 루트를 빌드 자리로 본다.

처음 적을 때는 "Vercel → Settings → General → Root Directory 를 `app-v2` 로 지정해야 한다"고 썼는데,
그 뒤 `app-v2/` 의 내용을 저장소 루트로 **통째로 평탄화**했다(`app-v2` 폴더 자체가 이제 없다).
지금 루트 `package.json` 에 `next: 14.2.35` 가 정상적으로 들어 있다 — **2026-08-14 감사에서 확인함.**
Root Directory 를 손대지 않아도(빈 값 = 저장소 루트) 이제 빌드가 잡힌다.

⚠ 다만 Vercel 프로젝트 설정에 예전에 **`app-v2` 로 지정해 둔 값이 이미 저장돼 있다면** 그건 이제
틀린 값이다(리포에 그 폴더가 없으니). 그 값을 지우고 비워 두는 것(=루트)까지는 대시보드를 봐야
알 수 있다 — 이번 감사는 여기까지만 코드로 확인했고, 대시보드 값 자체는 사람이 확인해야 한다.

### ② `OLLAMA_PRIMARY_URL` 이 사설 IP 다 — ✅ 확인함, `.env.example` 에 적어 둠

로컬 `.env.local` 의 `OLLAMA_PRIMARY_URL`(팀 내부망 주소)과 `OLLAMA_FALLBACK_URL`(localhost)은
**Vercel 서버가 물리적으로 못 닿는 주소**다(사설 IP·루프백). 실제로 두들겨 확인한 대안:
`https://ollama.com/v1` (OpenAI 호환, 이 계정 `OLLAMA_API_KEY` 로 `/v1/models` 200 · `gpt-oss:20b` 로
실제 응답까지 받음). 다만 `glm-5.2`(`:cloud` 포함)는 이 계정에 구독이 없어 403
(`this model requires a subscription`) — 구독을 안 올릴 거면 `OLLAMA_PRIMARY_MODEL` 을
`gpt-oss:20b` 같은 무료 확인 모델로 바꿔야 AI 추천이 실제로 답을 준다. 안 바꿔도 서비스가 죽진
않는다 — `lib/ai.ts` 가 403 을 '못 붙음'으로 곱게 처리한다(§4-7 의 "20초 뒤 실패" 가 이 경우다).

### ③ SSE 스트림이 서버리스 시간 한도에 걸린다 — ✅ 적용함 (`stream/route.ts` 에 `maxDuration = 60`)

`app/api/m/[code]/stream/route.ts` 는 "자체 서버라 연결을 물고 있어도 된다"는 전제로 짜여 있었다
(develop-selfhost 라는 브랜치 이름 자체가 자체 호스팅을 가리켰다). Vercel 서버리스 함수는 실행
시간 한도가 있어 이 연결이 중간에 끊긴다. `maxDuration = 60` 을 넣어 끊기는 간격을 늘렸다 —
그래도 아예 안 끊기게는 못 한다(플랜별 상한이 다르다). 다행히 클라이언트(`app/m/[code]/ui.tsx`)가
`onerror` 에서 물러남을 두고 스스로 다시 붙게 짜여 있어서, 끊겨도 몇 초 반짝하고 이어진다 —
서비스가 죽지는 않는다.

### ④ 속도 제한이 인스턴스마다 따로 센다 — 알려진 채로 둠 (안 고침)

`lib/ratelimit.ts` 의 한도는 **이 프로세스의 메모리**에 쌓인다(파일 맨 위 주석에 이미 적혀 있다 —
"서버가 여러 대가 되면 대수만큼 한도가 곱해진다"). Vercel 이 여러 인스턴스를 띄우면 실제 한도가
느슨해진다(안전 쪽으로 어긋난다 — 더 세게 막히는 게 아니라 덜 막힌다). 사고를 완전히 막는 정도는
아니지만 여전히 막긴 막는다. 정확히 하려면 Vercel KV·Upstash 같은 공유 저장소로 옮겨야 하는데,
그건 별도 인프라 선택이 필요해 이번엔 안 건드렸다.

### ⑤ 배포한 뒤 새로 확인할 것 (§4 에 더해)

9. Root Directory 가 **비어 있는지(=저장소 루트)** — `app-v2` 평탄화 뒤로는 이게 맞다.
   옛날에 `app-v2` 로 지정해 둔 값이 아직 남아 있으면 그걸 지운다 (Vercel 프로젝트 설정 화면에서 직접 본다)
10. `NEXTAUTH_URL` 이 실제 Vercel 도메인으로 돼 있는지 (비어 있거나 localhost 로 남아 있으면 카카오
    로그인 왕복이 어긋날 수 있다)
11. `KAKAO_REDIRECT_URI` 를 Vercel 도메인으로 바꿨다면 **카카오 콘솔에도 그 주소를 새로 등록**했는지
    (콘솔에 등록된 JavaScript 키 도메인도 같이 추가해야 지도가 뜬다)
12. AI 추천을 한 번 눌러 실제로 후보가 나오는지 — 위 ② 문제로 안 나오면 모델을 바꿨는지 확인

## 7 · 2026-08-14 최종 감사 (배포수준 점검 두 가지)

이 문서 전체를 처음부터 끝까지 다시 읽고 "✅ 적용함" 이 안 붙은 항목을 코드로 직접 대조했다.

### 고친 것

- **없다.** §3⑦(모임 조회·SSE 횟수 제한)이 유일하게 "미적용처럼 보였지만 실은 이미 코드에 있던" 항목이었다 —
  `lib/ratelimit.ts`·`app/api/m/[code]/route.ts`·`app/api/m/[code]/stream/route.ts` 를 직접 열어 확인했고,

### 발견만 하고 안 고친 것 (왜)

- **§2 ①②③ (`MOIMER_SALT`·`NEXTAUTH_URL`·`KAKAO_REDIRECT_URI`)** — 코드는 이미 `process.env` 를
  정확히 읽는다. 안 된 것은 코드가 아니라 **배포 시점에 실제 값을 넣는 사람의 일**이라 이번엔 안 건드렸다.
- **§2 ⑤ (첫 요청이 모임을 지운다)** — 정상 동작이라고 이미 정리돼 있다. 고칠 버그가 아니라 알아 둘 사실이다.
- **§3 ⑧ (초대 코드만으로 이름·출발지 이름이 보임)** — 설계 판단이 필요하다(문서에 이미 "일부러 그런 것일 수
  있다"고 적혀 있다). 코드로 바로 고칠 일이 아니라 목록에 그대로 남긴다.
- **§3 ⑨ (로그)** — 확인 결과 새는 것 없음, 다만 `lib/ai.ts:122` 는 프롬프트 자체를 찍는 줄이 하나 늘면
  그 순간부터 참가자 좌표가 샐 수 있는 자리라고 이미 경고돼 있다. 지금은 안전해 손대지 않았다.
- **§6 ④ (속도 제한이 인스턴스마다 따로 센다)** — 문서에 이미 "Vercel KV·Upstash 같은 별도 인프라 선택이
  필요해 안 건드렸다"고 정확히 적혀 있다. 그 판단이 여전히 맞다고 보고 그대로 둔다.
- **부하 시험** — ODsay·카카오·Ollama Cloud 등 실제 외부 API 에 대량 요청을 보낼 수 있어 이번 감사
  범위에서 뺐다. 사람 허락이 있어야 한다.

### §6① 은 감사 중에 상태가 바뀌어 있는 것을 발견해 문서를 함께 고쳤다

원래 "Vercel Root Directory 를 `app-v2` 로 지정해야 한다"고 적혀 있었는데, 그 뒤 `app-v2/` 를 저장소
