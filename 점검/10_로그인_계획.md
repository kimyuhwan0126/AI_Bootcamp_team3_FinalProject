## 🚨 가장 먼저 — 소금을 가른다 (이걸 안 하면 사고가 난다)

`lib/auth.ts:14`
```ts
const SALT = process.env.NEXTAUTH_SECRET ?? 'moimer-dev-salt';
```

이 한 줄이 **PIN 해시**와 **참가자 쿠키 서명** 둘 다에 쓰인다.
`NEXTAUTH_SECRET` 을 넣는 순간 소금이 바뀌어:

- 기존 참가자들의 **PIN 이 전부 안 맞는다** — 아무도 못 돌아온다
- 기존 **쿠키 서명이 전부 깨진다** — 다들 모임에서 튕긴다

**고칠 방향**: PIN·쿠키용 소금을 따로 둔다. 기본값은 지금 것(`moimer-dev-salt`) 그대로여야
이미 저장된 해시가 계속 맞는다.
```ts
const SALT = process.env.MOIMER_SALT ?? 'moimer-dev-salt';   // 로그인과 무관
```
그 뒤에야 `NEXTAUTH_SECRET` 을 넣는다.

**확인 방법**: 넣기 전에 참여자 하나를 만들어 PIN 을 적어 두고,
넣은 뒤 그 PIN 으로 돌아와지는지 본다. `flowtest` 84건도 그대로여야 한다.

## 사람이 해야 할 것 (내가 못 한다)

1. `.env.local` 에 두 줄
   ```
   KAKAO_CLIENT_SECRET=콘솔에서_받은_값
   NEXTAUTH_URL=http://127.0.0.1:3000
   ```
2. **콘솔 Redirect URI 확인** — NextAuth 는 이 주소로만 돌아온다:
   `http://127.0.0.1:3000/api/auth/callback/kakao`
   (`localhost` 가 아니라 **`127.0.0.1`**. `.env.local` 의 `KAKAO_REDIRECT_URI` 는 옛 설계 것이라 다를 수 있다)
3. 로그인 화면이 생기면 **한 번 눌러 보고 결과 알려 주기**

**카카오 계정 정보(아이디·비밀번호)는 필요 없다. 받아서도 안 된다.**
세션 쿠키도 필요 없다 — 사람이 한 번 로그인하면 `users` 에 줄이 생기고,
그 뒤로는 그 uid 로 세션을 직접 발급해 쓸 수 있다.

## 🔑 결정이 더 붙었다 (논의124·125·126)

| 논의 | 무엇 |
|---|---|
| **124** | 방장은 **카카오 계정으로 판정한다** — 쿠키가 아니라 계정이 열쇠 |
| **125** | **방장 넘기기를 없앤다** — 논의97 을 대체한다. 방장은 모임에서 못 나간다(지우는 것으로 갈음) |
| **126** | 참여자 사칭은 **감수한다** — 다만 쿠키 서명은 값이 0이라 남긴다 |

### 이것으로 풀리는 것
- **논의122(방장 벽돌)** — 쿠키를 잃어도 다시 로그인하면 방장으로 돌아온다
- **논의88(`users` 쌓임)** — 로그인한 사람만 줄이 생긴다
- **방장 사칭** — 쿠키를 주워도 계정이 없으면 못 한다

### 새로 생기는 것
- **옛 모임은 방장이 로그인 안 한 상태다.** 그것들은 쿠키로 판정해야 한다 —
  한동안 규칙이 둘이 된다(새 모임은 늘 계정, 옛 모임은 쿠키)
- **논의69(마지막이 나가면 모임 삭제)가 사실상 안 도는 규칙이 된다** —
  방장이 늘 남아 있어 활동 중인 사람이 0이 될 수 없다. 버려진 모임은 논의104 가 맡는다
