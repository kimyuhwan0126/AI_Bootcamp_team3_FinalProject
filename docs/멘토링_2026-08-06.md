## 1. UI/UX 플로우 발표 피드백

### 전체 평가

- 순서도 구성과 AMG UX 방향 긍정적
- 하단 탭 구성 (홈 / 탐색 / 모임 / 내정보) 방향 적절
- 디스코드에 작업 결과물 올리는 방식 괜찮음
- 기존 HTML 프로토타입과 다른 UI인데, 방향 자체는 나쁘지 않음

> ⚠️ 하단 탭은 이후 v19·2차에서 **3개(홈/모임/내정보)** 로 확정됐다. '탐색'은 홈에 흡수.

### 핵심 피드백 — 방장/참여자 화면 분리 필요

- 현재 방장과 참여자 화면이 섞여 있어 **구현 시 꼬일 가능성 높음**
- 해결책: 화면을 복제해서 "방장에게는 어떻게 보이는지" / "참여자에게는 어떻게
  보이는지" **두 벌로 명확히 분리**
- 방장 아닌 사람은 **핵심 투표 결과만** 보면 됨 — 굳이 비활성화 처리 불필요

## 2. 핑(Ping) 등록 기능 — **가장 중요한 기능으로 확정**

### 핵심 아이디어

- 참여자/방장이 지도에 핑을 찍어 지역 후보를 등록
- 핑 찍으면 **시·군·구 단위로 자동 묶기** (또는 서울은 지하철역 기준)
- 지역 투표 단계를 별도로 두지 않고 **핑 등록 = 투표로 통합 가능** → 단계 간소화
- 많이 찍힌 곳이 자동으로 지역으로 선정되는 방식
- 방장은 **AI 추천 버튼으로** 지역 후보를 추가할 수 있음 (**참여자는 조회만**)
- 참여자는 핑 찍지 않아도 되고, **방장이 다음 단계로 강제로 넘어갈 수 있음**

### AI 호출 시점

- 지역 후보 등록 시 AI 추천으로 후보 추가 가능
- 지역 확정 후 해당 지역의 가게/지점 AI 추천

### 핑 등록 UX 개선 제안

- 링크 진입할 때 정보 입력 받지 말고, **핑 찍은 후 모달로 추가 정보 수집**
- 배달의민족처럼 특정 가게를 바로 찍는 방식도 고려 → 단계 건너뛰기 가능
- 방장이 투표 귀찮을 경우 **바로 확정**할 수 있는 옵션도 있으면 좋음

## 3. 결과 화면 피드백

- **결과 보고 끝나는 흐름 방지 필요** — 구글 캘린더 등록, 재투표, 이전 화면
  돌아가기 등 흡수 장치 필요
- 결과 화면에서 가장 중요한 건 **지도 뷰** — 초기에 만들었던
  "출발지 → 중간지점 경로" 지도 화면을 결과 화면에 통합하는 게 **아이덴티티**
- 표 형태의 결과보다 **지도로 시각화**하는 게 사용자 반응 더 좋음
- 결과에서 지점 마음에 안 들면 지점으로 돌아가고, 투표 마음에 안 들면 재투표
- **힘 줄 곳: 핑 등록 + 결과 화면 지도 뷰 두 가지에 집중**

## 4. 개발 방향 조언

### 프론트엔드/앱 스택

- 지금은 Next.js 웹으로 구현 (로컬 시연 우선 목표)
- 프로젝트 끝나고 시간 나면 **Expo(React Native)** 로 앱 전환 — 기술스택 거의
  동일, 앱 심사만 추가됨
- 앱 심사(TestFlight 등)는 남은 기간 안에 어려우므로 발표 자료에
  "앱 권한 어디까지 받을 수 있는지" 명시하는 것으로 대체

> ⚠️ 레포 `CLAUDE.md` §3-2 는 안드로이드를 **PWA + TWA(Bubblewrap)** 로 가기로 정해 뒀다
> (`docs/APK.md`). Expo 전환은 "프로젝트 끝나고"라는 단서가 붙은 제안이다.

### 개발 우선순위

- **아키텍처 먼저 만들 필요 없음** — "화면에 필요한 데이터가 제일 먼저"
- 테스트 데이터(JSON)를 AI한테 만들게 시켜서 먼저 화면에 뿌리고 → 진짜 필요한 것만
  DB에 저장하는 순서로
- 사람들이 이 화면 써야 다음 화면 가니까, 그게 돌아가는 것부터 우선

### 개밥먹기(Dog Fooding) 강조

- 만든 것 직접 써보고 → 불편한 부분 회의 → 수정 루프가 제일 중요
- AI한테도 웹페이지 들어가서 직접 써보게 시킬 수 있음 (Playwright MCP 활용)
- **"내가 쓸 것 같다"가 판단 기준** — 4명이 계속 맞춰야 함

### 피그마 활용 방향

- 지금 만든 플로우를 피그마로 옮겨서 세밀하게 디자인 조정
- 그 디자인을 기준으로 HTML 구현 → Playwright로 테스트 루프
- 피그마 교육계정(학생 계정)으로 무료 이용 가능 — AI 기능도 한정적으로 사용 가능
- 피그마 → MCP로 읽거나 스크린샷으로 AI에게 전달 가능

## 5. Claude Code 활용 팁 (멘토 시연)

### 기본 활용

- 터미널 버전이 제일 최신 기능 먼저 반영됨 — 앱보다 터미널 추천
- `?` 입력하면 사용 가능한 단축키/기능 전체 확인 가능
- `Ctrl+B`: 백그라운드로 전환해서 비동기 작업 가능
- `BTW`: 개발 진행 중 궁금한 것 사이드로 질문 (개발 흐름 끊지 않음)
- ESC 두 번: 현재 작업 중단, 이후 "계속 진행해줘" 하면 이어서 작동
- 컨텍스트 길어지면 필요 없는 부분 잘라내는 게 토큰 절약에 중요

### 서브 에이전트 활용

- 서브 에이전트 = 격리된 컨텍스트에서 특정 역할 수행하는 AI
- 병렬로 여러 에이전트 동시 실행 가능 (개발 + 테스트 + 코드 리뷰 동시에)
- 비싼 모델(Opus)은 계획에, 싼 모델(Sonnet/Haiku)은 테스트에 배분하면 비용 효율적
- Ollama로 E2E 테스트 돌리면 토큰 비용 절약 가능

### 추천 플러그인 — Feature Dev

- Claude Code 터미널 내 `/plugin` → Feature Dev 설치
- 포함된 에이전트: 코드 아키텍처 설계 / 코드 익스플로러(코드 탐색) / 코드 리뷰
- 이 세 가지만 있으면 웬만한 개발 커버 가능
- 슈퍼파워즈 같은 복잡한 플러그인 불필요 — 기본 모델 성능이 좋아서 오히려 방해될 수 있음

### 핵심 철학

- AI한테 구현 맡기고 "AI가 한 번에 완벽하게 해줄 것"이라고 생각하면 절대 안됨
- 무한 루프 재시도로 원하는 결과 나올 때까지 토큰 태우는 게 맞는 방법
- 내가 "구현해야 할 것"과 "제외할 것"을 명확히 전달하는 능력이 핵심
- 깃허브에 올라온 코드를 Gemini한테 다시 물어보면 코드 이해에 더 효과적
- 패치노트를 롤 패치처럼 매일 확인 — Claude Code는 거의 매일 업데이트됨
