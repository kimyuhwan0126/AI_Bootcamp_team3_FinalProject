## 0. 2차 산출물이 무엇인가

1차 그릴링은 **순서도 HTML 5장**이었다. 2차는 **동작하는 프로토타입**이다.

```
docs/설계도/2차/
  moimer-app-kakao.html      진입점 (카카오맵 SDK)
  moimer-router.js           해시 라우터 — 화면 11대
  moimer-store.js            상태·역할·시뮬·AI (localStorage)
  moimer-core.js             지도·시트·핀·토스트 등 공통 부품
  screens/{home,hub,me,forms,region,place,result}.js
  moimer-{tokens,shell,screens}.css
  serve.js · start.cmd · .env.example
  motion-lab/                별도 Vite 앱 (모션 실험)
```

`start.cmd` 를 더블클릭하면 로컬에서 돈다. 카카오 키가 **없어도** 끝까지 굴러가게
행정동 39개 좌표표를 번들해 뒀다 — 우리 레포의 "키 없어도 전체 플로우"(CLAUDE.md §3-4)와 같은 원칙이다.

> 읽는 법: 각 파일 맨 위 주석이 그 화면의 규칙을 문장으로 적어 놨다.
> 코드보다 그 주석이 설계 산출물에 가깝다.

## 1. 그대로인 것 (v19 = 2차 = 현재 코드)

여기 있는 것들은 **다시 논의할 필요가 없다.**

| 항목 | 값 |
|---|---|
| 화면 수 | **11대** — 홈·모임·내정보·생성·참여·지역후보·지역투표·지점후보·지점투표·결과·지난 |
| 하단 탭 | **3개** (홈 / 모임 / 내정보) |
| 확정 범위 | `지역까지` / `지점까지`(기본) — 전체 분기축 |
| 지역까지 단계 | ping → vote-region → result (**지점 단계 건너뜀**) |
| 정원 | **8명** |
| 지점 반경 | **700m**, 확장 **1회 · 1.4km · 전원 공유** |
| 동 스냅 | `coord2regioncode` · 병합 키 = **행정동 코드** · 실패 시 좌표표 폴백 |
| 투표 시작 = 잠금 | 방장만 |
| 되돌리기(reopen) | 한 칸씩 · **표 유지** |
| 승격 | `지역까지` → `지점까지` 단방향 |
| 도착 신호등 | 모임 **당일만** · 지각은 분 입력 · 시간 없으면 잠금 |
| 결과 경로 계산 | **확정 후에만** |
| 모임 생성 | 카카오 로그인 필수 |
| 참여 | 초대 링크 + 이름 (비밀번호 없음) |

> 오늘(8/10) 구현한 **지점 미리보기 회색 원 → 누르면 후보**도 2차와 같은 모델이다.
> 2차는 거기에 **점선 반경 원**(`kakao.maps.Circle`)을 더 그린다 — 우리 코드엔 없다.

## 3. 팀이 결정할 것

발표까지 시간이 있으니 **전부** 하려 들지 말고 골라야 한다.
아래는 "고르기 쉬운 순서"로 놓은 것이지 권고 순위가 아니다.

### 값만 바꾸면 되는 것 (반나절)

- **① 후보 상한 5개** — 상수 하나 + 화면 문구. 근거도 명확하다("여섯 개를 놓고 고르라고 하면 표가 흩어져 1위가 안 나온다")
- **⑪ 카테고리 라벨** — 문자열
- **⑤ 모임 탭 필터 2줄** — 화면만

### 규칙이 바뀌는 것 (하루)

- **② AI 팔레트** — AI 결과를 후보에 바로 넣지 않고 담아 둔다.
  ⚠️ 지금 `aiRecommend` 는 후보를 직접 쓴다. 저장 위치가 하나 늘어난다
- **⑥ 재투표 분리** — 서버 액션 하나(`revote`) 추가. 동점 팝업에서 고른다
- **④ 홈 → 생성 인계** — 2차 방식(seedPings)이 v19의 '미배정 핑'보다 **훨씬 간단하다.**
  참여자가 고르는 절차가 없어지고, 홈에서 찍은 자리가 그냥 지역 후보가 된다

### 데이터 모델을 건드리는 것 (이틀+, 발표 전엔 위험)

- **③ 이동수단 4종** — `transport` 타입·DB 컬럼·이동시간 계산·UI 토글이 전부 바뀐다.
  ODsay 호출도 지하철/버스를 나눠야 의미가 있다
- **⑨ 바텀시트 · ⑧ 결과 시트화** — 화면 구조 전면 개편

### 부딪히는 것 — 먼저 답을 정해야 함

- **⑦ 참가자 색.** 2차 팔레트에는 **빨강·주황**이 있는데, 우리 규칙은
  "도착 신호등이 초록·노랑·빨강을 쓰므로 참가자 색에 그 계열을 넣지 않는다"(`CLAUDE.md` 색상 규칙)다.
  2차 색을 그대로 가져오면 **결과 화면에서 참가자 핀과 신호등이 같은 색**이 된다.
  → 2차 팔레트를 쓰되 빨강·주황을 빼거나, 신호등 표현을 색이 아닌 것으로 바꾸거나, 둘 중 하나

## 4. 지금 코드와의 관계

8/10 기준으로 **2차가 요구하는 것 중 이미 된 것**:

- 지점 미리보기 → 탭해서 후보 등록 (오늘 지도 회색 핀으로 구현)
- 지역 후보 삭제 (방장 임의 / 본인 것)
- 지도 핑 확인 시트 (2차는 바로 등록하지만, 우리는 오등록 제보가 있어 확인을 넣었다)
- 반경 700→1400 · 1회 · 전원 공유
- 되돌리기 사다리 · 표 유지

**2차에만 있고 우리에게 없는 것** 중 발표에 눈에 띄는 것은
**점선 반경 원**과 **후보 상한 표시(n/5)** 정도다. 둘 다 작다.
