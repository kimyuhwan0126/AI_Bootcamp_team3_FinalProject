## 2. 실사용자가 겪을 문제 (심각도순)

### 🔴 1. 추정값에 `실시간` 배지가 무조건 붙는다

`app/m/[code]/sections/TravelTimes.tsx` 의 `실시간` 칩은 **조건이 없다.**

```tsx
<span className="chip ok" style={{...}}>실시간</span>   // ← 항상 렌더된다
```

키가 하나도 없는 상태에서 찍은 실제 화면:

```
유환   ● 정시권     실시간   26분
지훈   ● 많이 늦음  실시간   1시간
서연   ● 많이 늦음  실시간   1시간 22분
민준   ● 많이 늦음  실시간   1시간 17분
```

**네 숫자 모두 직선거리 추정값이다.** 외부 API 를 한 번도 부르지 않았다.

같은 화면에서 행을 탭해 열리는 경로 상세 시트는 같은 구간을 이렇게 표시한다:

```
유환 · 서울역 → 홍대입구      [추정값]
실시간 경로를 가져오지 못해 추정값으로 표시해요
```

→ **목록은 "실시간", 상세는 "추정값".** 사용자는 탭하기 전에는 진실을 볼 수 없다.

⚠️ 이건 팀이 이미 한 번 고친 버그다. `app/page.tsx`(메인 화면)에는 `midLive`
판정이 붙어 `실 이동시간 기준` / `거리 추정으로 계산` 을 정직하게 바꿔 표시한다.
**같은 수정이 정작 제품의 본 화면인 `/m/[code]` 에는 안 들어갔다.**

- 원인: `/api/midpoint` 는 `recommendRegionsWithMeta` 를 써서 `live` 를 내려주는데,
  `app/api/meeting/route.ts` 의 `case "regions"` 는 `recommendRegions`(meta 없음)를
  쓰고 `{ok, regions}` 만 돌려준다. **모임 플로우에는 `live` 신호가 아예 없다.**

### 🔴 2. `많이 늦음` 은 본인이 말한 적이 없는데 뜬다

`TravelTimes.tsx:38`

```ts
const status = p.status ?? arrivalStatus(m, groupMins);   // 자가신고가 없으면 추정
```

`arrivalStatus` 는 **가장 빠른 사람 대비 차이**로 매긴다(8분 이하 초록 / 20분 이하 노랑 / 그 위 빨강).
즉 **누군가는 항상 `정시권`이고, 멀리 사는 사람은 자동으로 `많이 늦음`** 이 된다.

- 자가신고 배지와 추정 배지가 **모양이 완전히 같다.** 지훈이 아무 말도 안 했는데
  다른 사람 화면에는 빨간 `● 많이 늦음` 이 뜬다.
- 지각이 아니라 **거리**인데 단어는 "늦음"이다. 모임 분위기를 해칠 수 있는 표현이다.

### 🔴 3. 코드만 알면 남의 표를 던지고 방장 노릇을 할 수 있다

비밀번호는 **`join` 에서만** 검사한다. 그 외 모든 동작은 `participantId` 만 보는데,
**그 id 는 비번 없이 열리는 `GET /api/meeting?code=…` 응답에 그대로 들어 있다.**

실측(전부 성공):

| 시도 | 결과 |
|---|---|
| 비번 없이 상태 조회 | ✅ 모임명·참가자 이름·**출발지 주소·좌표** 전부 노출 |
| 남의 `participantId` 로 출발지 변경 | `{"ok":true}` |
| 남의 표 대신 던지기·덮어쓰기 | `{"ok":true}` |
| 방장 id 로 거점 확정 | `{"ok":true}` |
| 없는 id 로 투표 | ❌ 거부됨 (유일한 방어) |

이 앱은 **초대 코드를 카카오톡 단톡방에 뿌리는 것**이 전제다. 그 방을 보는 사람은
누구나 위 전부를 할 수 있다. 출발지는 대개 집·회사라 **개인 위치정보**다.

부수적으로 비밀번호는 **DB 에 평문 저장**이다(`db/schema.sql:23` 이 TODO 로 인정).

### 🟡 5. 캘린더에 **다음 주 토요일 저녁 7시**가 조용히 들어간다

결과 화면의 `📅 Google 캘린더에 추가` · `📄 .ics 다운로드` 는
`lib/calendar.ts` 의 `meetingSchedule()` 을 쓴다.

```ts
if (state.prefs.dateIso) { … }
else { /* 다음 토요일 19시 */ }
```

그런데 `prefs.dateIso`·`timeHhmm` 를 채우는 건 **AI 채팅 파서뿐**이고, 그 채팅은
**기본으로 꺼져 있다.** 방장이 쓰는 `meetTime` 액션은 자유 텍스트 `prefs.timeText`
하나만 저장한다 — 실측:

```
prefs = {"timeText": "8월 10일 저녁 7시"}      ← dateIso·timeHhmm 없음
```

→ **방장이 "8월 10일 저녁 7시"라고 입력해도, 캘린더에는 다음 토요일 19시가 잡힌다.**
경고 문구도, 되돌릴 방법도 없다. 사용자의 **진짜 캘린더에 잘못된 약속이 기록된다.**

### 🟡 6. 모르는 지명을 넣으면 **서울 어딘가 좌표**가 조용히 생긴다

카카오 지오코딩이 실패하면 `lib/geo.ts:106 geocode()` 로 떨어지는데, 사전에 없는 이름은
**문자열 해시로 좌표를 만들어낸다** (37.45~37.65, 126.85~127.15 = 서울 시내).

키 0개 상태 실측:

| 입력 | 나온 좌표 | 실제 |
|---|---|---|
| `제주공항` | 37.594, 127.129 | **서울 노원구 부근** (제주는 33.5, 126.5) |

추천에 반영된다. 키가 있는 프로덕션에서도 **카카오가 0건을 돌려주면 같은 경로**를 탄다
(오타·중의적 지명·신규 상호에서 흔하다).

### 3-2. 추정 모델은 얼마나 틀리나

`lib/geo.ts:130`

```ts
estMinutes(km, "transit") = round(6 + km × 3.0 × 1.6) = round(6 + 4.8 × km)
estMinutes(km, "car")     = round(8 + km × 2.2 × 0.9) = round(8 + 1.98 × km)
```

- 대중교통 **4.8분/km ≒ 평균 12.5km/h** 로 가정한다. 서울 지하철 도어투도어 실측과
  견주면 상당히 느린 가정이다.
- 게다가 거리는 **직선(haversine)** 이다. 실제 노선 거리는 더 길다.
- **고속철·고속버스 개념이 없다.** 거리가 멀수록 오차가 기하급수로 커진다.
- `memory/status.md` §1 에 이미 프로덕션 실측 기록이 있다:
  **`최대 220분 · 편차 136분`** ← 부발↔부천 실제 대중교통 2시간 안팎.

**결론: 이동시간은 대체로 실제보다 크게 나온다. 그런데 화면은 `실시간` 이라고 말한다.**

### 3-3. 그래서 답은

> **아니오 — 지금 상태로는 이동시간 숫자를 고객에게 그대로 보여주면 안 된다.**
>
> 값 자체가 추정인 것은 문제가 아니다. 팀은 이미 폴백을 설계했고, 경로 상세 시트는
> 그 사실을 아주 잘 밝히고 있다. **문제는 목록 화면이 그 숫자에 `실시간` 이라는
> 거짓 라벨을 붙이는 것**이다. CLAUDE.md §3-6 *"가짜 데이터를 실제인 것처럼 그리지
> 않는다"* 를 정면으로 어긴다.
>
> 나머지(모의결제·알림·캘린더 가져오기)는 전부 정직하게 표시돼 있다.
> **딱 이 한 군데가 앱 전체의 신뢰도를 깎고 있다.**
