## 2. 1차 ↔ 현재 코드 — **다른 것**

### A. 미배정 핑 이관 — 순서도에 있고 코드에 없다 → ✅ **2026-08-10 다르게 채움**

4번 순서도 하단에 `미배정 핑 이관` 상자가, 5번에는 홈→생성 화살표가 있다.
v19 §4-① 의 뜻은 "홈에서 찍은 출발지들을 모임으로 넘기고, **참여자가 들어와
자기 것을 고른다**".

- 코드: `app/page.tsx:1235` 에 **미구현임을 적어 둔 주석**만 있다.
  `startVote` 는 이관된 핑을 지우는 쪽(`lib/store.ts:1422`)만 이미 준비돼 있다.
- 2차는 이걸 **`seedPings`(나머지 출발지를 그냥 지역 후보로)** 로 바꿨다 → §3-①

> **2026-08-10 결론** (`lib/handoff.ts`): 넘기되 **무엇을** 넘길지는 2차와 다르게 정했다.
> - ✅ **첫 출발지** → 방장 출발지 · ✅ **홈에서 본 중간지점** → 첫 지역 후보
> - ❌ **나머지 출발지** — 안 넘긴다
>
> ⚠️ 2차처럼 나머지 출발지를 후보로 쓰면, 홍대·잠실에서 출발하는 모임의 후보가
> '홍대'·'잠실'이 된다. 한 사람은 집 앞이고 다른 사람은 가로질러 가야 한다 —
> **이 앱이 없애려는 상황 그 자체다.** 출발지는 사는 곳이지 만날 곳이 아니다.
> 대신 중간지점을 넘긴다. 그건 실제로 만날 만한 자리고, 홈에서 이미 본 답이다.
>
> v19 의 '참여자가 자기 것을 고른다'는 절차는 없어졌다 — 참여자는 어차피
> 참여할 때 자기 출발지를 직접 넣으므로 고를 것이 없다.

### B. '카카오톡 알리기' 가 결과 화면에만 있다 ⚠️

4번 순서도 상시 규칙: **"이벤트마다 '카카오톡 알리기'(상시 버튼 · 앱 설치자는 푸시)"**.

- 코드: `sections/ResultSection.tsx:302` **결과 화면 한 곳뿐**이다.
- 순서도대로면 지역 확정·지점 확정·투표 시작 같은 **이벤트마다** 눌러 알릴 수 있어야 한다.
- 발표에서 "카톡으로 굴러가는 앱"을 보여주는 장면이라 눈에 띄는 차이다.

### C. 동점 → **재투표** 갈래가 없다 ⚠️

4번 순서도: `동점?` → **`방장 — 재량 선택` 또는 `재투표`** 두 갈래.

- 코드: 재량 확정(`confirmManual`)만 있다. `재투표` 라는 말은 `lib/types.ts:263`
  주석("재투표는 덮어쓰기")에만 나오는데, 그건 **개인이 표를 바꾸는 것**이지
  방장이 판을 다시 여는 게 아니다.
- `reopenStep` 이 비슷하지만 **표를 유지**한다. 재투표는 **표만 지우고 후보는 유지**다 — 다른 동작이다.
- 2차가 이 둘을 명시적으로 분리해 놨다 → §3-③

### D. 자동 추천이 핑 자리를 먼저 차지한다 ⚠️ (설계와 코드가 부딪히는 곳)

4번 순서도의 지역 단계는 **`지도에 핑`** 으로 시작하고, AI 는 **점선(=선택)** 이다.
그래야 `후보 수? → 0개 = 시작 불가` 분기가 의미를 갖는다.

- 코드: `app/api/meeting/route.ts:333` `case "regions"` 가 출발지가 하나라도 있으면
  `recommendRegions` 로 **후보 3곳을 항상 채운다.**
- 결과: 아무도 핑을 안 찍어도 후보가 3개다 → **"0개 = 시작 불가" 분기가 실행되지 않는다.**
- 이건 버그가 아니라 **미해결 설계 충돌**이다. 1차·2차 둘 다 "사람이 먼저"인데
  코드만 "AI가 먼저"다.

### E. 반경 700m 를 **지도에 안 그린다** (사소)

4번: `반경 700m 표시`. 코드는 숫자·문구로만 알린다. `KakaoMap.tsx` 에 `Circle` 이 없다.
2차는 점선 원(`kakao.maps.Circle`)을 그린다. 작업량 작고 화면 효과는 크다.

### F. 모임 탭 필터 (사소)

4번/v19 는 "단계4 + 역할2 + 지난1 = **7종**", 코드는 `전체` 를 더해 **8칩**
(`app/meetings/page.tsx:22~29`). 실질 같음 — 2차는 두 줄 구성을 제안 → §3-④

## 3. 1차 ↔ 2차가 **서로 다른** 곳 (여기가 진짜 결정거리)

코드를 어느 쪽에 맞출지 정해야 하는 항목이다. 전체 13건은
[`설계_v20_2차그릴링_대조.md`](설계_v20_2차그릴링_대조.md) §2 에 있고, 여기엔
**§2 의 미구현 항목과 직접 얽힌 4건**만 뽑았다.

| | 1차(v19) | 2차 | 지금 코드 | 코드 관점 |
|---|---|---|---|---|
| ① **홈 → 생성 인계** | 미배정 핑 → 참여자가 고름 | 첫 출발지=방장, 나머지=**지역 후보 씨앗** | 방장 것만 | 2차가 **훨씬 싸다.** 고르는 화면이 아예 없어진다 |
| ② **AI 결과 자리** | 후보에 바로 | **팔레트에 담고 사람이 올림** | 바로 (자동까지) | 2차를 따르면 §2-D 충돌이 **저절로 풀린다** |
| ③ **재투표** | 동점 팝업의 한 갈래 | **되돌리기와 분리** (표만 삭제) | 없음 | 서버 액션 `revote` 하나면 된다 |
| ④ **후보 상한** | 지점 상한 없음 | **지역·지점 모두 5개** | 상한 없음 | 상수 + `n/5` 표시 |

> ①②③ 은 서로 붙어 있다. **②(AI 팔레트)를 채택하면** 지역 후보가 사람 핑만으로
> 차므로 `candidateGate` 의 `0개 = 시작 불가` 가 살아나고, 그 자리를 ①(seedPings)이
> 채워 준다. 셋을 따로 결정하면 앞뒤가 안 맞을 수 있다.

## 5. 멘토링(2026-08-06)을 겹쳐 보면

원본: [`멘토링_2026-08-06.md`](멘토링_2026-08-06.md). 멘토님이 우선순위를 한 줄로 주셨다.

> **"힘 줄 곳: 핑 등록 + 결과 화면 지도 뷰 두 가지에 집중"**

이 기준으로 위 §2·§3·§4 를 다시 세우면 이렇게 된다.

| 멘토 지적 | 코드 상태 | 판정 |
|---|---|---|
| **결과 화면 = 출발지→중간지점 지도 뷰** (아이덴티티) | 이미 있다 — `MeetingClient.tsx:384` 가 경로를 그리고 캘린더 버튼도 있다 | ✅ 됨 |
| **핑 등록이 가장 중요한 기능** | 자동 채움이 후보를 먼저 채워 핑이 주인공이 아니었다 | ❗ **§2-D** 와 같은 지점 |
| **"방장은 AI 추천 *버튼*으로 후보를 추가"** | 자동이었다. 게다가 LLM 버튼은 `NEXT_PUBLIC_FF_AI_VOTE` 뒤에 숨어 있어 **버튼 자체가 안 보였다** | ❗ 2026-08-10 고침 |
| **결과에서 재투표로 빠져나갈 것** | 재량 확정만 있다 | ❗ **§2-C** 와 같은 지점 |
| **방장/참여자 화면 분리** | `isLeader` 분기가 **8개 파일 39군데**에 흩어져 있다 | ➕ 대조표에 없던 새 항목 |

멘토링과 §2 가 **독립적으로 같은 곳을 가리켰다** — D(자동 채움)와 C(재투표)다.
반대로 §2 의 A(미배정 핑 이관)·E(반경 원)·F(필터)는 멘토님 우선순위 밖이다.

### 그래서 순서

1. **자동 채움 → 방장 버튼** (D · 멘토 "힘 줄 곳 ①") — ✅ **2026-08-10 완료**
2. **방장/참여자 화면 갈라내기** (멘토 액션 아이템 1번) — ✅ **2026-08-10 완료**
3. **결과 화면 재투표 버튼** (C · 멘토 "흡수 장치") — ✅ **2026-08-10 완료**

§4 의 나머지(A·E·F·후보 5개 제한)는 위 셋이 끝난 뒤에 본다.

### 1번은 무엇을 바꿨나 (2026-08-10)

- `case "regions"` 는 이제 **후보를 만들지 않는다** — 이미 있는 후보의 이동시간·편차만 갱신한다
- 방장 버튼이 **항상 보인다.** LLM 플래그가 꺼져 있으면 점수 기반 추천(`suggestRegions`)으로 떨어진다
- 후보 0개 화면이 **처음으로 실제로 뜬다** → "지도를 눌러 등록 / 방장은 추천 버튼" 안내를 넣었다
- ⚠️ 부수 발견: **지도 SDK 가 못 뜬 기기에서는 핑을 찍을 수 없었다.** 자동 채움이
  그 사실을 가리고 있었다 — 카카오 키가 실패하면 지역 단계가 막다른 길이 된다.
  폴백 지도에도 탭 등록을 넣어 막았다 (`MapPanel.tsx` `unpos`)
- 옛 동작이 필요하면 `.env.local` 에 `NEXT_PUBLIC_FF_AUTO_REGIONS=1`

### 2번은 무엇을 바꿨나 (2026-08-10)

- **[`lib/roles.ts`](../lib/roles.ts) 신설** — `isLeader &&` 39군데를
  `abilitiesOf(역할, 단계, 지난모임)` **한 표**로 모았다. 화면은 `can.startVote` 처럼
  **행동 이름**으로 읽는다. 나중에 역할이 늘어도 여기만 고친다
- **[`ParticipantBar`](../app/m/[code]/sections/ParticipantBar.tsx) 신설** — 참여자 화면 하단이
  **비어 있었다.** 이제 "지금 무슨 칸 · 내가 할 일 / 진행률"을 말하고 한 일은 `✓` 로 표시한다.
  **버튼은 하나도 없다** (멘토: "굳이 비활성화 처리 불필요")
- 참여자에게 보이던 **비활성 '방장만 결제할 수 있어요' 버튼 제거**
- `check:screens` 에 **참여자 시점 4대** 추가 — 이 스크립트는 오래도록 방장 시점만 훑었다

> ⚠️ **경계 두 개를 헷갈리지 말 것.**
> `lib/roles.ts` 는 **보이게/안 보이게** 하는 층이다. **막는 것은 서버**(`lib/store.ts`)가 하고,
> 서버는 이 파일을 믿지 않는다. 그리고 `stepOf` 는 서버 `phaseStepOf` 와 **같은 규칙이어야 한다** —
> 어긋나면 "눌리는데 서버가 거부하는" 버튼(v12 버그)이 다시 생긴다.

### 3번은 무엇을 바꿨나 (2026-08-10)

**`revote`** — 후보는 그대로 두고 **표만 초기화**한다. §2-C 의 빈칸이 이걸로 메워졌다.

| | 단계 | 후보 | 표 |
|---|---|---|---|
| `reopenStep` (되돌리기) | 한 칸 **내려간다** | 유지 | **유지** |
| `revote` (재투표) | 투표 칸에 **머문다** | **유지** | **지운다** |

- 투표 칸 → 그 자리에서 표만 비운다 (1차 순서도 4번의 `동점 → 재투표` 갈래)
- 결과 화면 → 확정을 풀고 그 단계의 투표 칸으로 (**지역 확정은 유지** — 한 칸만 되돌린다)
- 등록 칸 → 표가 없으니 거부
- 버튼은 **결과 화면**(되돌리기 옆)과 **투표 칸의 동점일 때**. 둘의 문구를
  `후보부터 다시` / `표만 초기화` 로 갈라 놓았다 — 나란히 두면 무엇이 다른지 모른다

> 💡 한 번 틀렸던 것: `confirm` 을 "투표 칸부터"로 좁혔더니 `modals.spec` 이 바로 걸렸다.
> 멘토링 §2 에 *"방장이 투표 귀찮을 경우 **바로 확정**할 수 있는 옵션도 있으면 좋음"* 이 있고
> 서버도 main 단계 확정을 허용한다 → **등록 칸에서도 확정은 된다**(작은 보조 버튼).
> 하단 방장 바의 큰 확정 버튼만 투표 칸부터다.
