# 발표 당일 — 로컬 실행 + 팀원 기기 접속 (LAN 시연)

> **시연 구조**: 발표자 노트북에서 `npm run dev:lan` 으로 띄우고,
> 같은 Wi-Fi에 붙은 팀원 폰들이 **`http://<노트북IP>:3000`** 으로 접속한다.
> Vercel 배포판이 아니라 **로컬 서버 하나**를 여러 기기가 함께 쓴다.

```
                    ┌──────────────────────────────┐
                    │  발표자 노트북                │
                    │  next dev -H 0.0.0.0 -p 3000 │
                    │  ↕ Neon (또는 인메모리)       │
                    └───────────┬──────────────────┘
                                │ 같은 Wi-Fi (LAN)
        ┌───────────────┬───────┴───────┬───────────────┐
     팀원A 폰        팀원B 폰        팀원C 폰        방장(노트북)
   192.168.x.y:3000 로 접속 · 초대 링크는 자동으로 이 주소가 된다
```

---

## 0. 이 구조에서만 생기는 제약 — 먼저 읽을 것

| 항목 | 상태 | 대응 |
|---|---|---|
| **카카오맵 SDK 도메인** | 🔴 **등록 필요** | 개발자 콘솔에 `http://192.168.x.y:3000` 등록 (§3) |
| **카카오 로그인 Redirect URI** | 🔴 **등록 필요** | 같은 콘솔에 콜백 주소 등록 (§3) |
| **노트북 IP가 바뀜** | 🔴 **매번 재등록** | 발표 직전 리허설에서 확정 (§3-3) |
| 초대 링크 | ✅ 문제 없음 | 코드가 `location.origin` 을 쓴다 — IP 접속이면 링크도 IP로 나간다 |
| 현재 위치(GPS) | ✅ 지금은 문제 없음 | 코드에 `geolocation` 미사용. **앞으로도 쓰지 않는다** (§5) |
| 방화벽 | 🟡 확인 필요 | 3000 인바운드 허용 (§4) |
| DB | 🟡 선택 | Neon(인터넷 필요) 또는 인메모리 (§6) |

> ⚠️ **`http://` 다.** LAN IP에는 인증서를 붙일 수 없어 HTTPS가 아니다.
> 브라우저가 **비보안 출처(insecure origin)**로 취급하므로 GPS·카메라·알림 권한 API가
> 막힌다. 지금 코드는 그중 아무것도 안 쓰고 있어 무사하다 — **이 상태를 유지한다.**

## 1. 실행

```bash
npm install
npm run dev:lan       # = next dev -H 0.0.0.0 -p 3000
```

`-H 0.0.0.0` 이 핵심이다. 이게 없으면 노트북 자신(`localhost`)에서만 열리고
**다른 기기에서는 연결 자체가 안 된다.**

터미널에 뜨는 `Network: http://192.168.x.y:3000` 이 팀원들에게 알려줄 주소다.

## 2. 노트북 IP 확인

| OS | 명령 | 보는 곳 |
|---|---|---|
| Windows | `ipconfig` | `Wi-Fi` 어댑터의 **IPv4 주소** |
| macOS | `ipconfig getifaddr en0` | 출력 그대로 |
| Linux | `hostname -I` | 첫 번째 값 |

`192.168.*` 또는 `10.*` 로 시작하면 맞다.
`127.0.0.1`(자기 자신)이나 `169.254.*`(DHCP 실패)면 **Wi-Fi 연결부터 다시** 봐야 한다.

> 팀원 폰은 **같은 Wi-Fi**에 있어야 한다. 폰이 LTE/5G면 안 된다.
> 회사·학교 Wi-Fi가 **기기 간 통신 차단(AP isolation)**을 걸어 두면 이 구조 자체가 막힌다
> → **§7 대비책**.

## 3. 카카오 개발자 콘솔 등록 — 발표 전 필수

`https://developers.kakao.com` → 내 애플리케이션 → 해당 앱

### 3-1. 카카오맵 SDK — 사이트 도메인

**[앱 설정 > 플랫폼 > Web > 사이트 도메인]** 에 추가:

```
http://192.168.x.y:3000
```

등록하지 않으면 지도 SDK가 뜨지 않는다.
(코드는 원인을 구분해 안내한다 — "키 없음" vs "도메인 미등록", `KakaoMap.tsx`)

### 3-2. 카카오 로그인 — Redirect URI

**[제품 설정 > 카카오 로그인 > Redirect URI]** 에 추가:

```
http://192.168.x.y:3000/api/auth/kakao/callback
```

**`.env.local` 은 안 고쳐도 된다** (2026-08-10 변경).
서버가 `redirect_uri` 를 **들어온 주소 그대로** 만들어 보낸다:

| 접속 주소 | 서버가 보내는 redirect_uri |
|---|---|
| 방장 노트북 `http://localhost:3000` | `http://localhost:3000/api/auth/kakao/callback` |
| 팀원 폰 `http://192.168.x.y:3000` | `http://192.168.x.y:3000/api/auth/kakao/callback` |

> **왜 이렇게 바꿨나** — 예전엔 `.env.local` 값 하나로 고정해 보냈다. 그러면 폰에서
> 로그인해도 카카오가 **그 폰 자신의 `localhost`** 로 돌려보내서, 로그인이 영영
> 끝나지 않는다. 폰에는 그 주소에 아무것도 없기 때문이다.
> (2026-08-10 팀원 폰 `http://10.40.2.177:3000` 에서 실측)

**단, 콘솔 등록은 여전히 필요하다** — 두 주소를 **둘 다** 등록한다:

```
http://localhost:3000/api/auth/kakao/callback     ← 방장 노트북용
http://192.168.x.y:3000/api/auth/kakao/callback   ← 팀원 폰용
```

> ⚠️ 카카오는 redirect_uri 를 **글자 단위로** 비교한다 — 포트·슬래시 하나만 달라도 거부된다.
>
> 💡 **폰에서 무엇을 등록해야 하는지 바로 확인하는 법** — 그 폰으로 열어본다:
> `http://192.168.x.y:3000/api/auth/kakao?debug=1`
> `등록해야_할_RedirectURI` 줄을 **복사해서 그대로** 콘솔에 붙여넣으면 된다.

> ⚠️ **v14에서 이미 경고된 항목이다** — "카카오 OAuth redirect 는 사내망 IP 에서 제약 가능".
> 사설 IP 등록이 거부되면 §7의 대비책으로 간다.

### 3-3. IP가 바뀌면 전부 다시 등록해야 한다

DHCP라 노트북을 껐다 켜거나 Wi-Fi를 바꾸면 IP가 달라진다. 그러면 위 두 등록이 전부 무효다.

**대응 (권장 순서)**
1. 발표 **당일 아침** 발표장 Wi-Fi에 붙어 IP를 확정하고 그때 등록한다
2. 가능하면 공유기에서 **DHCP 고정 할당**을 걸어 둔다
3. 리허설 때 쓴 IP와 본 발표 IP가 다를 수 있으니 **등록 화면을 열어둔 채** 시작한다

여러 후보 IP를 **미리 다 등록해 두는 것도 된다** (카카오는 도메인·Redirect URI를 복수로 받는다).
리허설 IP + 예상 IP를 함께 넣어 두면 당일 손댈 일이 줄어든다.

## 4. 방화벽

첫 실행 때 OS가 "네트워크 접근을 허용할까요?" 를 물으면 **허용(개인/사설 네트워크)** 을 누른다.
놓쳤거나 여전히 접속이 안 되면:

- **Windows**: 제어판 → Windows Defender 방화벽 → 앱 허용 → `Node.js` 확인
  (또는 관리자 PowerShell)
  ```powershell
  New-NetFirewallRule -DisplayName "Moimer 3000" -Direction Inbound -LocalPort 3000 -Protocol TCP -Action Allow
  ```
- **macOS**: 시스템 설정 → 네트워크 → 방화벽 → 옵션 → `node` 수신 허용

**확인**: 팀원 폰 브라우저에서 `http://192.168.x.y:3000` 이 열리면 끝이다.

## 5. 쓰면 안 되는 것 — HTTP 비보안 출처

`http://` LAN 접속에서는 브라우저가 다음을 **차단**한다:

- `navigator.geolocation` (현재 위치)
- 카메라 · 마이크
- 알림 권한 (`Notification.requestPermission`)
- Service Worker (→ **PWA 설치·앱 푸시도 이 시연에서는 안 된다**)

**현재 코드는 이 중 아무것도 안 쓴다** (확인함). 앞으로 구현할 때도:

- 홈의 📍 버튼은 **GPS가 아니라 지도 중심 이동 / 검색**으로 만든다
- v16의 "앱 푸시"는 **이 시연 범위 밖**이다. 알림은 **카카오톡 알리기 버튼**으로만 보여준다
  (v18에서 "상시 버튼만"으로 정리돼 있어 설계와도 어긋나지 않는다)

## 6. 데이터 저장 — Neon vs 인메모리

| | Neon (`DATABASE_URL` 설정) | 인메모리 (미설정) |
|---|---|---|
| 인터넷 | **필요** | 불필요 |
| 서버 재시작 | 데이터 유지 | **전부 소멸** |
| 여러 기기 동시 접속 | ✅ | ✅ (로컬은 프로세스 하나라 문제 없음) |
| 발표 중 코드 수정 | 안전 | **hot reload에 데이터가 날아갈 수 있음** |

**권장: Neon.** 발표장 인터넷이 되면 `DATABASE_URL` 을 넣고 간다.
인터넷이 불안하면 인메모리로도 시연은 되지만, **발표 중에는 파일을 저장하지 않는다**
(Next dev의 hot reload가 서버 모듈을 다시 불러오면서 `Map` 이 비워질 수 있다).

> 참고: `CLAUDE.md` 의 "DB 모드에서는 인메모리 캐시를 두지 않는다" 규칙은
> **Vercel 서버리스 인스턴스 간 불일치** 때문이다. 로컬 단일 프로세스에는 해당하지 않지만,
> 코드는 같으니 그대로 둔다.

## 7. 대비책 — LAN이 막혔을 때

발표장 Wi-Fi가 AP isolation을 걸었거나, 카카오가 사설 IP 등록을 거부하면:

| 방법 | 방식 | 대가 |
|---|---|---|
| **A. 노트북 핫스팟** | 노트북이 Wi-Fi를 쏘고 폰들이 거기 붙는다 | 발표장 인터넷 불필요. **Neon은 못 씀**(노트북이 인터넷 없으면) |
| **B. 폰 핫스팟** | 폰 하나가 핫스팟, 노트북+나머지 폰이 붙는다 | 인터넷도 같이 된다. 가장 안정적 |
| **C. Vercel 배포판** | 기존 배포 URL 사용 | HTTPS·도메인 문제 전부 해소. **단 로컬 시연이라는 목표에서 벗어남** |

**권장: B(폰 핫스팟)를 기본으로 준비한다.** 인터넷도 되고 IP도 우리가 통제한다.
핫스팟 IP(보통 `172.20.10.x`)를 **미리 카카오에 등록**해 두면 당일 전환이 즉시 된다.

C는 최후 수단으로 살려 둔다 — 배포판이 살아 있는지 발표 전에 한 번 열어 본다.

### 🔍 한 줄 점검 — `npm run check:live`

서버를 띄운 채(다른 터미널) 아래를 돌리면 **DB·외부 API·4인 동시성**을 한 번에 본다.

```bash
npm run dev          # 터미널 1
npm run check:live   # 터미널 2
```

실제로 모임을 하나 만들어 4명을 넣고 **동시 투표**까지 시켜본 뒤 스스로 지운다 —
조회가 아니라 **왕복**이라 "쓰기가 진짜 되는지"까지 확인된다.
카카오 Redirect URI 포트가 dev 포트와 맞는지도 함께 본다(로그인 거부의 단골 원인).

> 💰 외부 API 를 실제로 호출한다(ODsay 무료 한도 1,000콜/일). 반복 실행으로 태우지 않는다.

LAN 주소로도 볼 수 있다 — 폰이 들어오는 그 주소로 점검하는 게 더 정확하다:

```bash
CHECK_BASE=http://192.168.x.y:3000 npm run check:live
```

### 📱 폰에서 보는 점검 — `/health`

`check:live` 는 **노트북에서** 도는 스크립트다. 그런데 발표에서 막히는 건 대부분
**폰 쪽**이다(다른 Wi-Fi · 방화벽 · IP 변경 · 카카오 미등록). 그래서 폰으로 직접 여는
화면을 따로 뒀다:

```
http://192.168.x.y:3000/health
```

여기서 기기마다 확인되는 것:

| 항목 | 무엇을 잡아내나 |
|---|---|
| **접속한 주소** | 방장이 `localhost` 로 열었으면 경고 — 그 상태로 만든 초대 링크는 팀원 폰에서 안 열린다 |
| **데이터 저장** | `Neon` 이면 기기 간 공유, `인메모리` 면 서버 재시작 시 소멸 |
| **이 기기의 Redirect URI** | 폰마다 값이 다르다. 복사 버튼으로 그대로 콘솔에 붙여넣으면 된다 |
| **기기 간 연동** | 첫 기기가 [점검 시작] → 링크를 단톡방에 → **팀원 폰이 목록에 뜨는지** |

마지막 칸이 핵심이다. 다른 기기가 참여했는데 **새로고침 없이** 목록에 안 나타나면
그 폰은 서버에 못 붙은 것이다 — 발표는 거기서 멈춘다. 미리 잡는다.

> 이 화면은 **실제 모임 API 를 그대로** 쓴다(만들기·참여·조회만, 외부 API 0콜).
> 여기서 초록이면 발표 경로도 초록이다. 점검이 끝나면 [점검 끝] 으로 기록을 지운다.

## 9. 자주 막히는 지점

| 증상 | 원인 | 조치 |
|---|---|---|
| 폰에서 아예 안 열림 | `-H 0.0.0.0` 누락 / 방화벽 / 다른 Wi-Fi | §1 · §4 · §2 |
