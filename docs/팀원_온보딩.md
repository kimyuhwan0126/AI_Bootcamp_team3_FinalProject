# ✅ 3단계 — 첫 PR 내보기 (연습 삼아)

```bash
git checkout develop && git pull origin develop
git checkout -b feat/내기능이름

# ... 작업 ...

npm run verify        # 타입 + 빌드 + 브라우저 스모크
git add -A && git commit -m "feat: 무엇을 했는지"
git push -u origin feat/내기능이름
```

GitHub 에서 **`develop` 으로** PR 을 엽니다. (`main` 아닙니다)

- CI 가 자동으로 돕니다 (`verify (flags-off)` · `verify (flags-on)`)
- **초록 안 뜨면 머지 버튼이 아예 막힙니다**
- 초록이면 **Squash and merge**

> 첫 `npm run verify` 는 크로미움(~100MB)을 자동으로 받습니다. 두 번째부터는 즉시.

## 커밋 메시지 접두사

| 접두사 | 뜻 |
|---|---|
| `feat:` | 기능 추가 |
| `fix:` | 버그 수정 |
| `refactor:` | 동작 그대로, 구조만 |
| `docs:` `test:` `chore:` | 문서 · 테스트 · 잡일 |

본문은 한글로 써도 됩니다. 예: `feat: 날씨 스코어러 추가`

## 머지 방식

| 머지 | 방식 |
|---|---|
| `feat/*` → `develop` | **Squash and merge** |
| `develop` → `main` | **Create a merge commit** (통합 담당자만) |

# ✅ 4단계 — 매일 지킬 것

## ① `develop` 을 매일 받아오기

```bash
git fetch origin develop && git merge origin/develop
```

**오래 묵힌 브랜치가 진짜 충돌의 원인입니다.** 파일이 겹쳐서가 아니라
3주치 차이를 한 번에 합치려니까 터집니다.

## ② 만드는 중인 기능은 플래그 뒤에

```bash
# .env.local — 커밋되지 않는 개인 파일
NEXT_PUBLIC_FF_AI_CHAT=1     # 내가 개발 중인 것만 켠다
```

절반만 된 상태로 합쳐져도 남의 화면이 안 깨집니다.
**상수를 직접 고치지 마세요** — 브랜치마다 값이 달라져 머지할 때마다 충돌납니다.

# ⚠️ 6단계 — 우리가 실제로 겪은 함정

읽어두면 며칠을 아낍니다. 전부 **에러 없이 조용히 실패**하는 것들입니다.

## ① 빌드 통과 ≠ 화면 렌더

`npx tsc --noEmit` 과 `npm run build` 를 **둘 다 통과**하고도 모임 상세 화면이
통째로 안 그려진 적이 있습니다.

**원인**: `useEffect` 를 조건부 `return` 뒤에 뒀습니다.
→ 훅은 **전부 조건부 `return` 위에** 두세요. 이제 `npm run lint` 가 잡아줍니다.

## ② `lib/store.ts` 호출에 `await` 빠뜨리기

전 함수가 async 입니다. `await` 를 빼도 **타입이 맞아서** 조용히 무동작합니다.

## ③ `backdrop-filter` 안에서는 `position: fixed` 가 갇힘

`.appbar` · `.leaderbar` · `.v8-bottomnav` · `.v8-header` 가 전부 씁니다.
그 안에서 전체화면 모달을 띄우면 헤더 안에 갇혀 잘립니다.
→ **`createPortal(…, document.body)`** 를 쓰세요.

## ④ 모달은 조건부 렌더라 빌드로 안 잡힘

prop 하나만 어긋나도 조용히 안 열립니다. 모달을 건드렸으면 **직접 열어보세요.**

## ⑤ "내 컴에선 되는데"

`npm run verify` 가 빈 환경에서 깨져 있던 적이 있습니다(개발자 PC 에만 있던
환경변수 때문에 안 보였음).
→ **"내 환경에서 되는지"가 아니라 "빈 환경에서 되는지"** 를 보세요.

## 🤖 AI 로 개발할 때 — 프롬프트에 규칙을 붙일 필요 없습니다

**`CLAUDE.md` 는 Claude Code 가 세션 시작할 때 자동으로 읽습니다.**
Claude 를 쓰든 Ollama+GLM 을 쓰든 — 모델이 아니라 **도구가 읽는 것**이라 똑같이 동작합니다.
규칙을 매번 프롬프트에 붙여넣으면 사람마다 달라지고 시간이 지나면 어긋납니다.

작업 시작할 때 이 정도면 충분합니다:

```
lib/scoring/CLAUDE.md 읽고 상권 밀집도 스코어러 만들어줘
```

폴더를 지정해 주면 그 폴더의 `CLAUDE.md` 를 먼저 보게 됩니다.
처음 시작할 땐 이것도 좋습니다:

```
memory/status.md 읽고 지금 상황 파악한 다음 시작하자
```

### 규칙이 지켜지는 3중 장치

| 층 | 무엇이 | 강제력 |
|---|---|---|
| **자동 로드** | 폴더별 `CLAUDE.md` | AI 가 알아서 따름 |
| **리뷰 강제** | `.github/CODEOWNERS` | 공용 파일 건드리면 리뷰 필요 |
| **기계가 차단** | CI + 브랜치 보호 | **초록 아니면 머지 자체가 막힘** |

사람 기억에 의존하는 층이 없습니다. 그게 설계 의도입니다.
