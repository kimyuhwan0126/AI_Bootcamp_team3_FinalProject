## 0. 한 줄 요약

각자의 출발지에서 **가장 공평한 중간 지점**을 찾아, **지역 투표 → 지점 투표 → 최종 확정**으로
모임 장소를 정한다. 모이머의 핵심은 **장소 결정**이다.

대화는 **카카오톡에서 한다**는 전제다. 앱 화면은 **투표 UI**로 그린다.
AI는 **방장이 누르는 추천 버튼 하나**뿐이다.

## 1. 화면 지도 — 11대

```
[하단 3탭]  ① 홈 /        ② 모임 /meetings        ③ 내정보 /me
                                (통합 허브)

[모임 흐름]
  ④ 모임 생성 ──▶ ⑤ 참여 폼 ──▶ ⑥ 지역 후보(핑) ──▶ ⑦ 지역 투표
   (방장)         (참여자)          (전원)              (전원)
                                                          │ 지역 확정
                        ┌─────────────────────────────────┤
          '지역까지' ───┘                                 └─── '지점까지'
                        │                                       │
                        │                    ⑧ 지점 후보 ──▶ ⑨ 지점 투표
                        │                       (전원)          (전원)
                        │                                       │ 지점 확정
                        └──────────────▶ ⑩ 결과 ◀───────────────┘
                                            │ 모임일 다음날
                                            ▼
                                       ⑪ 지난 모임 (읽기 전용)
```

하단 3탭은 **모든 화면 위에 항상 떠 있다.**

## 2. 상태기계 — Stage 4칸

| Stage | aiPhase | 상단 스텝탭 | 화면 | 하는 일 |
|---|---|---|---|---|
| `main` | `region` | 0 | ⑥ | 사람을 모으고 지역 후보 핑을 받는다 |
| `chat` | `region` | 0 | ⑦ | 지역 투표 |
| `chat` | `place` | 1 | ⑧ ⑨ | 지점 후보 등록 → 지점 투표 |
| `result` | `done` | 2 | ⑩ | 확정 — 모이는 일만 남았다 |

**지역 투표와 지점 투표는 같은 Stage(`chat`)다.** 구분하는 건 `aiPhase`뿐이라
화면 컴포넌트도 대부분 공유한다. 상단탭 번호도 여기서 계산된다.

> ⚠️ **상단 스텝탭은 이동 수단이 아니라 표시다.**
> 눌러서 지난 단계를 봐도 **조회만** 된다(`PastStepView`). 실제 Stage는 안 바뀐다.
> 단계를 되돌리는 건 **방장의 reopen 뿐**이다.

## 3. 전체 분기축 — 확정 범위

**모임 생성 시 방장이 고른다. 기본값 `지점까지`.** 이것이 전체 흐름을 가르는 축이다.

| | `지역까지` | `지점까지` (기본) |
|---|---|---|
| 지점 단계(⑧⑨) | **건너뜀** | 진행 |
| 목적 카테고리 | **숨김**(생성 폼에서도) | 5종 선택 |
| 결과 화면 경로 API | **호출 안 함** — 지도만 | 각자 출발지 기준 호출 |
| 지점 카카오 링크 | **숨김** | 표시 |
| 도착 신호등 | **숨김** | 표시 |
| 승격 | 방장 **'지점도 정하기'** 가능 | — |
| reopen 도착지 | 지역 투표 | 사다리 규칙(§6) |

**승격은 단방향이다.** `지역까지` → `지점까지`는 되지만 역방향은 없다.

## 4. 화면별 명세

### ① 홈 `/` — 중간지점 맛보기

로그인 없이 누구나. 지도 전체화면. 화면 상태 3종: `browse` · `clean` · `detail`.

- 출발지 검색·추가 (자동완성 · 최근 · **대중교통/자차 토글**, 기본 대중교통)
- 출발지 카드 슬라이더 (최대 8) — 색 배지, 탭하면 포커스→시트→숨김
- 기준 전환 **거리순 ↔ 시간순** — 결정론적(누가 계산해도 같은 답)
- **중간지점 1곳** 말풍선 핀 — 핀 드래그 시 재계산(`/api/midpoint`)
- 중간지점 확정 → **탐색 모드**(우하단 핀 버튼 · 카테고리 슬라이더)
- POI 핀 + 장소 바텀시트 (분류 · 도보 · 주소 · 전화 · 길찾기)

**전환 고리 — `[이 출발지들로 모임 만들기]`**
- **카카오 로그인 선행 필수.** 비로그인이면 로그인 유도 (v18)
- 홈 입력값을 생성 폼에 넘긴다 → 이때 **폼의 출발지 입력은 생략**된다 (v15)
- 홈 출발지들은 모임에 **'미배정 핑'**으로 남고, 참여자가 자기 것을 선택·수정한다 (v5)
- 미배정 핑은 **투표 시작 시 삭제**된다 (v9)

### ② 모임 탭 `/meetings` — 통합 허브

**모든 화면의 재진입 허브.** 투표함·모임원 탭은 여기로 통합됐다 (v6).

- **투표할 것 상단 고정** (🔔 배너)
- **필터 7종**: 단계 4(모집·지역·지점·확정) + 역할 2(방장·참여) + 지난 모임 1
- **시간순 정렬**
- `[+ 모임 만들기]` → ④
- 모임 카드 탭 → **그 모임의 현재 단계 화면**으로 이동
- 지난 모임 카드 탭 → ⑪ 읽기 전용

### ③ 내정보 `/me` — 설정

**저장은 전부 이 기기(localStorage). 계정 병합 없음** (v19).

- 카카오 로그인 / 로그아웃
- **기본 출발지** · **기본 이동수단**
- **기본 PIN** — 참여 폼 자동 채움
- 앱 푸시 알림 on/off
- 출발지·PIN은 **모임별로 개별 수정 가능**
- 자동 채움 조건은 **'내정보 기본값이 있으면'** 하나뿐이다 (v19가 v11을 단순화 — 로그인 여부 무관)

> 약관 등은 운영 전환 시. 지금은 위 4개뿐.

### ④ 모임 생성 — 방장 전용

**카카오 로그인 필수.** 원스텝 폼.

| 항목 | 규칙 |
|---|---|
| 모임 이름 | 필수 · 방장이 나중에 수정 가능 (v12) |
| 모임 시간 | **선택** · **과거 입력 불가** (v16) · 생성 폼에서 받는다 (v2가 result 입력에서 이전) |
| **확정 범위** | 지역까지 / **지점까지**(기본) |
| 목적 카테고리 | 5종 중 택1 · `지역까지`면 **숨김** · 방장 수정 가능 |
| 내 출발지 · 이동수단 | 방장도 원스텝에 포함 (v14) · **홈 경유면 생략** (v15) |
| 방장 이름 | 카카오 프로필 자동 + 수정 가능 (v14) |

`[만들기]` → 6자 참여코드 발급 → 초대 링크 `/m/{code}`

**목적 카테고리 5종** (카카오 분류 코드 매핑, v13):
`음식점` · `카페` · `술집` · `문화/놀이` · `야외`

### ⑤ 참여 폼 — 링크 진입

**비밀번호 없다** (v2에서 제거). 초대 링크만으로 들어온다.

| 항목 | 규칙 |
|---|---|
| 이름 | **원스텝 필수** · 중복이면 별칭 요청 팝업 |
| 출발지 | **원스텝 필수** · 자동완성 좌표 그대로 저장 · 내정보 기본값 자동 채움 |
| 이동수단 | 토글 (기본 대중교통) |
| 개인 PIN | **비로그인 참여자만** · 로그인 참여자는 계정 기반 복구라 생략 (v15) |

- **정원 8명.** 9번째는 **입장 거부** — 초과분은 유료 구간 구상 (v8)
- **PIN 시도 5회 제한** (v16) · 잠기면 방장 강퇴 → 재참여만
- 출발지 수정은 **핑 잠금 전까지** (v14)
- **늦은 참여자**: 확정 전이면 투표 가능, 확정 후엔 열람만 (v5)

### ⑥ 지역 후보 — 핑 등록 `main`

지도 전체화면. **누구나(방장 포함) 핑을 찍어 후보를 등록한다.**

- **동 스냅** — 카카오 `coord2regioncode` · **실패 시 좌표 폴백**
- **같은 동은 병합** · **인원당 1개** (+ AI 3곳)
- 병합 핑에서 사람이 빠지면 **그 사람 몫만 빠진다.** 마지막 한 명이면 후보 삭제 (v12)
- **후보에 이동시간을 표시하지 않는다.** 경로 API는 최종 확정 후에만 쓴다
- 참가자 핀 색은 `PIN_COLORS` 하나로만 관리 (→ `CLAUDE.md` 색상 규칙)
- 1.8초 폴링으로 전원 화면 동기화

**방장에게만 보이는 버튼 2개**: `[AI 추천]` · `[투표 시작]`

### ⑦ 지역 투표 `chat`/`region`

- **핀 탭 = 1표.** 1인 1표, **재탭으로 변경**
- **진행률 n/N + 미투표자 이름** — 방장의 확정 판단 근거
- `[지역 확정]`은 방장만 (`confirmManual`)

### ⑧ 지점 후보 — 반경 700m `chat`/`place`

**확정 지역 핀 중심 반경 700m**(도보 10분). **밖은 거부.**

- **반경 확장은 700 → 1400m, 1회 한정. 누구나 누를 수 있고 전체에 공유된다** (v15)
- 목적 카테고리가 **기본 포커싱** · 카테고리·검색 조회는 **전원 가능** (v10)
- 정렬: 가까운순 · **별점순**(카카오 웹 스크래핑, v13)
- **미리보기 핀(회색) 탭 → 후보 등록.** **상한 없음** (v7이 5개 제한 철회)
- 삭제: 방장은 임의 후보, 본인은 자기 후보
- **'가게' 아니라 '지점'** — 공원 등 비상업 장소를 포함하기 때문 (v6)

**반경 내 POI 0개면 선택 팝업** (v12):
① 반경 확장(700→1400m) ② 다른 카테고리·검색·AI 유도
→ 1400m에도 0개면 ②만 남는다 (v15)

### ⑨ 지점 투표 `chat`/`place`

**⑦과 규칙 완전 동일.** 조회 방법만 다를 뿐(카테고리·검색·AI), 투표·확정 UI는 같다.

### ⑩ 결과 `result`

**경로 API는 확정 후 여기서만 호출된다** (`route-detail` · `route-path`).

- 확정 결과 — 지역 / 지점 · 지도 · 카카오맵 길찾기 링크
- **모임 시간 · D-day** 표시 (생성 시 입력값 · 여기선 표시·변경만)
- **도착 신호등 — 모임 당일만 활성**
  - 🟢 도착 예정 / 🟡 지각 → **몇 분 지각? 입력 → 전원 공유** / 🔴 불참
  - **본인만 자기 항목을 바꾼다**
  - **시간 미입력이면 신호등 잠금 + 입력 유도 배너** (v7)
- **지점 카카오 링크 연결** — 카카오맵 상세로 이동 · **지점 모임만**
  - ⚠️ **'선입금' 명칭은 폐기됐다** (v17). 결제는 범위 외다
- `[카카오톡 알리기]` — **상시 버튼만. 자동 팝업 없음** (v18)
- `[되돌리기]` (방장) — reopen 사다리
- `[지점도 정하기]` (방장) — `지역까지` 모임의 승격

### ⑪ 지난 모임 — 읽기 전용

- **모임일 다음날** 자동 전환 · 시간 미입력이면 **마지막 활동 7일 후** (v9)
- **부활 불가.** 재모임 버튼 외 모든 버튼 비활성 (v16, v18)
- 함께한 멤버 목록 표시
- `[이 멤버로 재모임 만들기]` — **방장만**
  - **카카오 로그인 멤버만 자동 이전.** 비로그인은 재참여 (v17)
  - 생성 폼 프리필로 이동

## 5. 단계 규칙 (지역·지점 공통)

두 단계 모두 **'등록 → 투표 시작(잠금) → 투표 → 방장 확정'** 2단계다 (v8).

### 투표 시작 = 잠금

방장이 `[투표 시작]`을 누르면 **핑/후보가 잠긴다.** 이후 등록·이동 불가.
미배정 핑은 이때 삭제된다.

### 후보 수에 따른 분기

| 후보 수 | 동작 |
|---|---|
| **0개** | **투표 시작 불가** — 토스트. 등록 단계에 머무른다 |
| **1개** | **투표 생략** — 방장이 바로 확정 |
| **2개 이상** | 정상 투표 |

### 동점

**방장이 재량 선택하거나 재투표.** **재투표 횟수 무제한** (v15). 표는 유지된다.

### 늦은 표·핑

확정·잠금 순간에 도착한 표/핑은 **서버가 거부하고 토스트를 띄운다** — "단계가 바뀌었어요" (v12).

## 6. reopen 사다리 — 방장 되돌리기

**누를 때마다 한 칸씩** 되돌아간다:

```
확정  ──▶  투표 다시  ──▶  후보부터 다시
```

- **표는 유지된다.** 삭제된 후보의 표만 사라진다 (v10)
- `지역까지` 모임의 reopen은 **지역 투표로** 간다 (v4)
- **경계 reopen (지점 → 지역)**: 지점 데이터를 **보관**해 뒀다가
  - **같은 동으로 재확정되면 복원**
  - 다른 동이면 폐기 (v17)
- result로 복귀하면 **신호등은 유지**된다 (v17)

## 13-A. ⚠️ v19와 코드가 충돌하는 항목 — 별점

**v19는 코드보다 하루 늦게 나왔지만, 이 항목만은 코드가 앞서 있다.**

| | |
|---|---|
| **v19 (2026-08-07)** | "별점: PoC 는 **카카오 웹 스크래핑 유지**(배포 시 구글 Places 검토)" · 지점 정렬 "가까운순·**별점순**" |
| **코드 (2026-08-06, PR #54·#55)** | 웹 스크래핑을 **이미 걷어냈다.** `lib/ai-vote/web-kakao.ts` 삭제 → `api-kakao.ts`(카카오 **공식 API**). playwright 의존 제거. **`rating` 은 전부 `0`(= 정보 없음)** |

**왜 코드가 그렇게 갔나**: Vercel 서버리스에 크롬이 없어 스크래핑이 배포에서 동작하지 않았다.
공식 로컬 API에는 평점 필드 자체가 없다. 그래서 `rating: 0` = "정보 없음" 규약을 세우고
UI 3곳(`MeetingClient` · `ResultSection` · `ManualPickModal`)에 `rating > 0` 가드를 넣어
**별점이 없으면 별이 저절로 사라지게** 만들어 뒀다. mock의 가짜 별점(4.3~4.7)도 이때 0으로 지웠다
— *"존재하지 않는 가게가 실제 가게보다 더 실제처럼 보인다"* 는 `CLAUDE.md` §3-6 위반이었기 때문이다.

| **A. 별점 없이 간다** (권장) | 현 코드 유지. 지점 정렬은 **가까운순만** | v19의 '별점순' 정렬 1개 포기 |

| C. 구글 Places | 별점 확보 | 새 키 · **비용 발생** · v13에서 "배포 시 검토"로 미뤄둔 항목 |

> **A를 권장하는 이유**: 이 결정은 v13에서 *"PoC 는 유지, 배포 시 재검토"* 였고,
> 실제로 배포하면서 재검토가 이미 일어난 것이다. v19가 그 사실을 모른 채 v13 문구를
> 실어 나른 것으로 본다. 되돌리면 `CLAUDE.md` §3-6(가짜를 실제처럼 그리지 않는다)에
> 다시 부딪힌다.
>
> **팀 결정 사항이다** (`CLAUDE.md` §5 — Scope 는 팀이 판단). 결정되면 이 절을 지우고
> §4-⑧ 의 정렬 문구를 맞춘다.
