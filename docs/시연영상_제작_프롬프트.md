첨부한 `demo` 폴더로 **발표용 시연영상**을 만들어 줘.

## 배경

'모이머(Moimer)' 라는 서비스의 시연영상이다. 각자 다른 곳에서 출발하는 사람들이
**가장 공평한 중간 지점**을 찾아 모임 장소를 정하는 앱이다.
2026년 8월 21일 최종발표에서 튼다. **발표 규칙상 시연 + 발표를 합쳐 10분**이라
영상은 **90초~2분**이 적당하다.

## 재료

- `demo/steps/*.png` — 장면 사진 15장. 한 장에 **폰 4대가 가로로** 들어 있고,
  위에 장면 번호와 제목, 각 폰 아래에 누구 화면인지 적혀 있다.
  **파일명 앞 두 자리가 순서**다 (01 → 15).
- `demo/자막.txt` — 장면별 나레이션 원고. 사진과 1:1로 대응한다.

## 등장인물 (사진에 이미 표시돼 있음)

| 이름 | 역할 | 출발지 | 이동수단 |
|---|---|---|---|
| 유환 | 방장 | 일산 | 자차 |
| 지민 | 참여자1 | 노원 | 대중교통 |
| 서연 | 참여자2 | 수원역 | 자차 |
| 도윤 | 참여자3 | 인천 | 대중교통 |

**수도권 안에서 네 방향으로 흩어져 있고, 이동수단도 절반씩 다르다.**
이게 이 앱의 핵심 상황이다 — 넷 다 서울 도심이면 "중간을 찾는다"가 의미 없다.

## 만들 것

1. **본편 영상** — 장면 사진을 순서대로 이어붙인 90초~2분짜리 mp4
   - 해상도 1600×926 (사진 원본 크기) 또는 1920×1080 레터박스
   - 장면당 5~7초. 단, 아래 '강조할 장면'은 더 길게
   - 장면 전환은 **크로스페이드 0.3초** 정도로 부드럽게
   - 배경음악 없이 만든다 (발표장에서 말로 설명한다)

2. **자막** — 각 장면 하단에 한국어 자막을 얹는다
   - `demo/자막.txt` 의 문장을 쓰되, **말맛에 맞게 다듬어도 된다**
   - 글자는 크게 (발표장 뒤에서도 보여야 한다)

3. **`.srt` 자막 파일**도 따로 뽑아 줘 (나중에 수정하기 쉽게)

## 강조할 장면 — 여기가 이 앱의 핵심이다

| 장면 | 왜 중요한가 | 처리 |
|---|---|---|
| **05~07 참여** | 링크를 누르고 **지도를 탭하면 참여와 후보 등록이 한 번에** 끝난다. 회원가입이 없다 | 한 장면씩 또박또박, 각 6~7초 |
| **08 네 명이 모였습니다** | 한 명이 한 일이 **새로고침 없이** 다른 폰에 뜬다 | 방장 폰(맨 왼쪽)을 살짝 확대하거나 테두리 강조 |
| **09 각자 원하는 곳에 핑** | **핑 하나가 곧 후보이자 한 표**다. 별도 투표 화면이 없다 | 7초 이상. 네 폰에 핀이 퍼지는 게 보이게 |
| **15 각자 얼마나 걸리나** | 이 앱의 결론. 참가자별 이동시간과 신호등 색이 나온다 | 8초 이상. 이동시간 목록 부분을 확대(줌인)하면 좋다 |

## 직접 만들 때 (다른 세션에 안 넘기고)

`ffmpeg` 이 있으면 한 줄로 끝난다.

```bash
# 장면당 5초 슬라이드쇼
ffmpeg -framerate 1/5 -pattern_type glob -i "demo/steps/*.png" \
  -c:v libx264 -pix_fmt yuv420p -r 30 -vf "scale=1600:-2" demo/시연.mp4
```

`ffmpeg` 이 없으면 **파워포인트**로도 된다.

1. 새 프레젠테이션 → 슬라이드 크기를 `와이드스크린(16:9)` 로
2. `삽입 → 사진 앨범 → 파일/디스크` 로 `demo/steps` 의 15장을 순서대로 넣기
3. `전환` 탭에서 `밝기 변화`, 시간 `5초`, `자동으로 다음 시간` 체크
4. `파일 → 내보내기 → 비디오 만들기`

npm run dev              # 터미널 1
