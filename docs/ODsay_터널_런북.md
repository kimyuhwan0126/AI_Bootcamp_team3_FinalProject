# ODsay 터널 런북 — 배포에서 대중교통 실값 켜기

> **언제 쓰나**: Vercel 배포가 대중교통 이동시간을 `거리 추정` 으로만 보여줄 때,
> 화이트리스트에 등록된 노트북을 경유시켜 **실값**으로 바꾸는 절차.
>
> **왜 이렇게까지 하나**: ODsay 서버 키는 *호출하는 서버의 공인 IP* 를 화이트리스트에
> 등록해야 통하는데, **Vercel 서버리스는 나가는 IP 가 유동**이라 등록할 수가 없다.
> 그래서 등록된 IP 를 가진 노트북을 중계로 세운다.
>
> ```
> Vercel(유동 IP) ──→ Cloudflare Tunnel ──→ 노트북 프록시(등록된 IP) ──→ api.odsay.com
> ```
>
> 앞선 기록: `memory/status.md` § 터널 종단 확인(2026-08-05 양방향 성공) ·
> `docs/버전관리.md` § 릴리스 전 체크리스트

---

## 0. 준비물

| | 확인 |
|---|---|
| 노트북이 **화이트리스트에 등록된 네트워크** | 공인 IP 가 ODsay 콘솔 등록값과 같아야 한다. Wi-Fi 를 바꿨으면 **다시 등록**해야 한다 |
| `cloudflared` 설치 | `cloudflared --version` |
| `ODSAY_API_KEY` 실물 | 43자. `memory/status.md` 의 "올바른 키" 지문 `sha256` 앞자리 `3be0295c` 와 대조 가능 |
| 공유 비밀 문자열 | 아무 긴 문자열이면 된다. **노트북과 Vercel 양쪽에 글자 단위로 같게** 넣는다 |

> ⚠️ **`ODSAY_API_KEY` 는 노트북 프록시가 아니라 Vercel 에 넣는다.** 프록시는 키를
> 갖지 않는다 — 앱이 쿼리에 실어 보내고 프록시는 그대로 넘긴다.

---

## 1. 노트북에서 프록시 + 터널 기동

**터미널 1** — 중계 서버 (의존성 0, `npm install` 불필요)

```bash
ODSAY_PROXY_SECRET='여기에-긴-문자열' node scripts/odsay-proxy.mjs
```

```
[proxy] http://127.0.0.1:8787 → https://api.odsay.com
[proxy] 허용 경로: /v1/api/searchPubTransPathT · /v1/api/loadLane
[proxy] x-proxy-secret 검사 ON (길이 20)
```

**터미널 2** — 터널

```bash
cloudflared tunnel --url http://localhost:8787
```

출력에서 **`https://<무작위>.trycloudflare.com`** 를 복사한다. 이게 `ODSAY_BASE_URL` 이다.

> 🔴 **Quick Tunnel 주소는 재시작마다 바뀐다.** 터널을 다시 켜면 이 절차의 3~4번을
> 처음부터 다시 해야 한다. **터널을 먼저 띄우고 그 주소로 환경변수를 넣는 순서**를 지킨다.

---

## 2. 💰 0콜 생존 확인 — 환경변수를 만지기 전에

터널 주소 뒤에 `/healthz` 를 붙여 **브라우저로** 연다:

```
https://<무작위>.trycloudflare.com/healthz
```

```json
{ "ok": true, "upstream": "https://api.odsay.com", "secretRequired": true,
  "count": { "ok": 0, "unauthorized": 0, "notFound": 0, "upstreamError": 0, "timeout": 0 } }
```

이게 뜨면 **터널 → 프록시 구간이 살아 있다** (ODsay 는 아직 한 번도 안 불렀다).
안 뜨면 여기서 멈춘다 — Vercel 을 건드려도 소용없다.

| 증상 | 원인 |
|---|---|
| Cloudflare 502 / 1033 | 터널은 떴는데 8787 에 프록시가 없다 → 터미널 1 확인 |
| 연결 자체 실패 | 터널 주소 오타, 또는 터널이 죽음 |

---

## 3. Vercel 환경변수 — **Preview 부터**

프로덕션은 `main` 이고 발표를 앞두고 있으니 실험대로 쓰지 않는다.

`Vercel → 프로젝트 → Settings → Environment Variables`

| 이름 | 값 | 스코프 |
|---|---|---|
| `ODSAY_API_KEY` | ODsay 서버 키 | ☑ Preview |
| `ODSAY_BASE_URL` | 1번에서 복사한 `https://….trycloudflare.com` | ☑ Preview |
| `ODSAY_PROXY_SECRET` | 1번에서 쓴 그 문자열 | ☑ Preview |

> 🔴 **이미 들어 있는 값이 있으면 "수정"하지 말고 삭제 후 재등록한다.**
> 스코프 체크만 바꾸는 방식이 반영되지 않은 사례가 있다(2026-08-04, **3회 시도 모두 실패**).
> 지금 배포에 박혀 있는 `ODSAY_BASE_URL` 은 **8/5 에 넣은 죽은 주소**일 가능성이 높다.
>
> ⚠️ `ODSAY_PROXY_SECRET` 불일치가 **8/4 실패의 진짜 원인**이었다 — 프록시가 401 을 줬는데
> 당시 앱이 로그 없이 삼켰다. 지금은 프록시 로그에 `401` 이 찍히고 `/healthz` 집계에도 쌓인다.

## 4. 재배포 — 저장만으로는 반영되지 않는다

환경변수는 **넣는 시점이 아니라 배포 시점에 적용된다.** `Deployments → 해당 Preview → Redeploy`.

> ⚠️ **`deploy.commit` 으로는 재배포 여부를 알 수 없다** — Redeploy 는 같은 커밋으로 새 배포를
> 만들어서 값이 그대로다. **Deployments 목록의 시각**을 봐야 한다.
> (2026-08-04: 이걸 몰라 같은 값을 세 번 확인했다.)

**`/api/status` 로 확인** (💰 0콜):

```json
"odsay": true, "odsayProxy": true, "odsayProxyAuth": true,
"deploy": { "env": "preview", "branch": "…" }
```

셋 중 하나라도 `false` 면 그 값이 안 들어갔거나 재배포가 안 된 것이다.

## 5. 종단 확인 — 💰 약 20~30콜

Preview URL 홈을 열고 출발지를 2~3개 넣는다.

> 🔴 **`시간순` 버튼을 반드시 누른다.** 홈 기본값은 **거리순**(`app/page.tsx:83`)이고,
> **거리순은 외부 API 를 아예 부르지 않는다** — 직선거리로만 잰다. 그래서 거리순으로 보면
> 터널이 완벽히 살아 있어도 배지가 항상 `거리 추정` 이다(`page.tsx:949`).
> 화면 상단 `[기준: 거리순] [시간순]` 에서 **시간순**을 고른다.

> 🔴 **처음 써 보는 좌표로 한다.** `routeCache` 에 TTL 이 없어서 **이미 캐시된 좌표쌍은
> 터널이 죽어도 실값이 나온다.** 리허설에서 쓴 좌표로 테스트하면 오판한다.

**기대 결과** — 중간지점 카드 배지:

| 상태 | 배지 |
|---|---|
| ✅ 성공 | **`전원 경로 기준`** |
| ❌ 일부 실패 | `일부 거리 추정` |

> ⚠️ 문구는 2026-08-05 에 바뀌었다. 옛 배포를 볼 때는 `실 이동시간 기준` / `거리 추정으로 계산`
> 을 찾아야 한다. **지금 코드는 `전원 경로 기준` / `일부 거리 추정` 이다.**

**같이 볼 것**: 터미널 1 의 프록시 로그에 `[proxy] 200 /v1/api/searchPubTransPathT?…apiKey=***`
가 흐르는지. 여기가 조용하면 앱이 터널로 오지 않은 것이다(= `ODSAY_BASE_URL` 미반영).

---

## 6. 반증 테스트 — **이게 진짜 검증이다**

터널을 끄고(터미널 2 에서 `Ctrl+C`), **또 다른 새 좌표**로 다시 돌린다.

→ **`일부 거리 추정` 으로 바뀌면** 배지가 실제 상태를 반영한다는 뜻이다.
→ 그대로 `전원 경로 기준` 이면 캐시된 좌표를 쓴 것이다. 좌표를 바꿔 다시 한다.

끝나면 터널을 다시 켜고 **새 주소로 3~4번을 다시** 한다(주소가 바뀌었다).

---

## 7. Production 승격 — 6번을 통과한 뒤에만

3번과 같은 값을 **Production 스코프**로 추가하고 재배포한다.
`/api/status` 에서 `deploy.env: "production"` 과 `odsay/odsayProxy/odsayProxyAuth` 셋 다 `true` 확인.

---

## 8. 되돌리기

문제가 생기면 **환경변수 3개를 삭제하고 재배포**한다 → `odsay: false` 로 돌아가
전부 거리 추정으로 폴백한다(앱은 깨지지 않는다). 화면이 흰색이면 Vercel `Instant Rollback`.

---

## 9. 알고 시작할 것 — 구조적 한계

이 방식은 **노트북이 켜져 있고 터널이 살아 있어야만** 동작한다.

| 상황 | 결과 |
|---|---|
| 노트북 절전·종료 | 배포 서비스가 **조용히** 추정값으로 떨어짐 |
| Wi-Fi 변경 | 공인 IP 변경 → 화이트리스트 불일치 |
| 터널 재시작 | 주소 변경 → 환경변수 수정 + **재배포** |

> **심사위원이 발표 뒤 다른 날에 링크를 누르면** 노트북은 꺼져 있다 → 추정값이 보인다.
> 그래서 이 터널은 "시연 중 품질을 올리는 장치"이지 "공개 링크를 고치는 장치"가 아니다.
> 공개 링크의 바닥을 올리려면 `lib/geo.ts` 의 `estMinutes` 보정이 따로 필요하다
> (실측상 대중교통 추정이 실값의 **1.5~3배**: `docs/검증_실키_2026-08-05.md` §B 대조표).

💰 **비용**: 종단 확인 약 20~30콜 (ODsay 무료 1,000콜/일). `/healthz` 는 0콜.

## 부록 — 프록시를 💰 0콜로 시험하기

`ODSAY_UPSTREAM` 에 로컬 replay 서버를 끼우면 ODsay 를 한 번도 부르지 않고
터널·중계·앱 전 구간을 확인할 수 있다.

```bash
ODSAY_PROXY_SECRET='...' ODSAY_UPSTREAM=http://127.0.0.1:9911 node scripts/odsay-proxy.mjs
```

평상시에는 넣지 않는다 — 비어 있으면 진짜 `api.odsay.com` 으로 간다.
